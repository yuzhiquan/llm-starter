# 第 1 篇精读｜猜下一个词

> 原文：llm-01-next-token.md ｜ 前置：无（系列起点） ｜ 核心一句话：大模型只做一件事——给定前文，算出词表上每个 token 当下一个的概率。

## 0. 三句话抓住它

- 一次前向只算下一个 token 的 50257 维分布。
- Softmax 把 logits 变概率，T 只改陡峭度。
- 生成是同一操作的循环，其余能力都是副产品。

## 1. 这一篇在补哪个洞

这是系列第一篇，没有上一篇可承接。它要补的洞是日常使用留下的那套错误心智模型。

你按下回车，看到字一个个冒出来，很自然会假设内部流程是"读懂问题 → 检索知识 → 组织语言 → 输出"。原文把这三个动词全部否掉：没有读懂，没有检索，没有一次性输出。

于是本篇只回答一个可验证的问题：一次 `model(input_ids)` 究竟返回什么？把这个返回值循环起来，为什么看起来像在回答问题？答案就是 Next Token Prediction，它是后面九篇共同的地基——每一篇都在解释这条流水线上的一个环节。

## 2. 概念逐层拆

### 2.1 Next Token Prediction（下一个词预测）

**是什么**：给定序列 x₁…xₜ，输出 P(xₜ₊₁ | x₁…xₜ) 在整个词表上的分布。

**为什么需要**：若把目标定义为"生成整段回答"，一段文本只有一个模糊的对错信号；拆成每个位置一个 50257 类分类任务，一段 100 token 的文本就提供 100 个监督样本。

**在系统里的位置**：既是训练目标，也是运行时每一步的全部计算。

**记住这个数**：生成 N 个 token = N 次前向、N 个分布。

### 2.2 logits（未归一化得分）

**是什么**：最后一层线性层直接吐出的实数，每个 token 一个，可正可负，和不为 1。

**为什么需要**：网络内部只会做加法和乘法，无法直接满足"非负且和为 1"的约束；先输出无约束的 logits，把约束留到 softmax 一次性施加。

**在系统里的位置**：输出端，softmax 之前。

**记住这个数**：GPT-2 每个位置 50257 个；输入 3 个 token 时 `outputs.logits` 形状是 `[1, 3, 50257]`。

### 2.3 Softmax

**是什么**：P(i)=e^(zᵢ)/Σⱼe^(zⱼ)，把任意实数向量压成非负、和为 1 的向量。

**为什么需要**：不归一化就无法采样、无法算交叉熵；指数函数保证正数，同时把领先者放大。

**在系统里的位置**：输出端归一化；第四篇会看到 Attention 的权重也用它。

**记住这个数**：两个 logit 相差 5.8，概率比就是 e^5.8≈330。

### 2.4 Temperature（温度）

**是什么**：先令 z←z/T 再 softmax；T 为正实数，默认 1.0。

**为什么需要**：同一个模型既要写代码（要稳定）又要写诗（要多样），重训不现实，只能在解码时调分布。

**在系统里的位置**：解码阶段，前向之后、采样之前，不属于模型本体。

**记住这个数**：`generate.py` 默认对比 0.3 / 1.0 / 1.5 三档。

### 2.5 Greedy 与 Sampling

**是什么**：Greedy 每步取 argmax；Sampling 按概率分布抽一次（`torch.multinomial`）。

**为什么需要**：Greedy 可复现但容易重复退化；Sampling 有多样性，代价是同一输入两次结果不同。

**在系统里的位置**：解码策略，运行时的最后一环。

**记住这个数**：`multinomial(probs, 1)` 每步只抽 1 个 token。

### 2.6 自回归循环（Autoregressive Loop）

**是什么**：把新 token 拼回输入，整段重新前向，再预测下一个。

**为什么需要**：模型没有可写回的内部状态，唯一的"记忆"就是越来越长的输入序列。

**在系统里的位置**：生成循环；第七篇的 KV Cache 只复用中间结果，不改变这个语义。

**记住这个数**：生成 30 个 token 就是 30 次前向；朴素实现第 k 步要重算前 k−1 个位置。

### 2.7 词表（Vocabulary）

**是什么**：模型认识的全部 token 的集合，大小固定，ID 从 0 到 V−1。

**为什么需要**：分类任务的类别数必须固定，这 50257 个 token 就是 50257 个类。

**在系统里的位置**：输入端分词与输出端分类共用同一张表。

**记住这个数**：GPT-2 的 50257 = 50000 个高频子词 + 256 个基础字节 + 1 个结束符。

## 3. 手算推演

原文只给了概率、没给 logits。为了让 top1 复现 99.2%，我取下面 5 项：前四名 + 其余 50253 个 token 打包成一个等效项。这组 logits 不是从 checkpoint 读出来的，是按原文概率反推的手算用值；结构与结论和原文一致。

先看" much"这一项，体会 T 只在指数里做除法：

- T=1.0：10.0 → e^10.0 = 22026.47
- T=0.7：10.0÷0.7 = 14.2857 → e^14.2857 = 1.6003×10⁶
- T=1.5：10.0÷1.5 = 6.6667 → e^6.6667 = 785.77

**T = 1.0（基准）**

| token | logit | e^logit | 概率 |
|---|---|---|---|
| ` much` | 10.0 | 22026.47 | 99.21% |
| ` very` | 4.2 | 66.69 | 0.300% |
| `,` | 4.2 | 66.69 | 0.300% |
| `much` | 3.1 | 22.20 | 0.100% |
| 其余 50253 个（打包） | 3.04 | 20.91 | 0.094% |
| 合计 | — | 22202.94 | 100% |

**T = 0.7（保守）**

| token | logit | logit÷0.7 | e^z | 概率 |
|---|---|---|---|---|
| ` much` | 10.0 | 14.2857 | 1.6003×10⁶ | 99.94% |
| ` very` | 4.2 | 6.0000 | 403.43 | 0.0252% |
| `,` | 4.2 | 6.0000 | 403.43 | 0.0252% |
| `much` | 3.1 | 4.4286 | 83.81 | 0.0052% |
| 其余 | 3.04 | 4.3429 | 76.93 | 0.0048% |
| 合计 | — | — | 1601287.8 | 100% |

**T = 1.5（奔放）**

| token | logit | logit÷1.5 | e^z | 概率 |
|---|---|---|---|---|
| ` much` | 10.0 | 6.6667 | 785.77 | 94.20% |
| ` very` | 4.2 | 2.8000 | 16.44 | 1.971% |
| `,` | 4.2 | 2.8000 | 16.44 | 1.971% |
| `much` | 3.1 | 2.0667 | 7.899 | 0.947% |
| 其余 | 3.04 | 2.0267 | 7.589 | 0.910% |
| 合计 | — | — | 834.15 | 100% |

把三张表压成一张：

| T | P(much) | P(very) | P(much)/P(very) | 形态 |
|---|---|---|---|---|
| 0.7 | 99.94% | 0.0252% | 3967 | 近乎确定性 |
| 1.0 | 99.21% | 0.300% | 330 | 原文基准 |
| 1.5 | 94.20% | 1.971% | 47.8 | 第二名抬头 |

三个可复用的结论：

**一、概率比只由 logit 差决定。** 两项相除，分母 Σe^z 约掉，得到 P₁/P₂=e^((z₁−z₂)/T)。这里 z₁−z₂=5.8，T=1 时 e^5.8=330.3，T=0.7 时 e^8.2857=3967，T=1.5 时 e^3.8667=47.8。

**二、T 改不了排序。** 除以正数 T 是单调变换，e^(z/T) 对 z 仍单调，任何两个 token 的大小关系不变。T 只改变"领先多少"。

**三、小概率的压缩幅度被直觉低估。** T 从 1.0 降到 0.7，top1 只从 99.21% 涨到 99.94%，看着只多 0.7 个百分点；但错误概率从 0.79% 掉到 0.06%，差了 13 倍。反过来，T=1.5 时第二名从 0.3% 涨到 1.97%，涨了 6.6 倍——这才是个位数百分比变化的真实含义。

## 4. 代码逐行

### predict.py：单步预测

```python
input_ids = tokenizer.encode(prompt, return_tensors="pt")
```
第 30 行。分词，并把 Python list 变成 torch 张量、补上 batch 维。运行看到 `Token IDs: [10449, 345, 845]`，形状 `[1, 3]`。

```python
outputs = model(input_ids)
next_token_logits = outputs.logits[0, -1, :]
```
第 39–42 行。一次前向拿到所有位置的 logits；`[0]` 取 batch 内第一个样本，`[-1]` 只取最后一个位置，`:` 保留全部 50257 个词。运行看到 `词表大小: 50257 个 token`。

```python
probabilities = torch.softmax(next_token_logits, dim=0)
```
第 48 行。在词表维归一化。此处已切片成一维，所以 `dim=0`；若没切片，应写 `dim=-1`。运行看到 top1 为 99.2%。

```python
top_probs, top_indices = torch.topk(probabilities, top_k)
bar = "█" * int(prob / 2)
```
第 51–59 行。取前 10 名并画条形图；99.2÷2 取整等于 49 格。运行看到第 1 名 49 个方块，第 10 名之后合并成"剩余 50247 个 token 共占 0.1%"。

```python
top1_prob = top_probs[0].item()
top5_prob = top_probs[:5].sum().item()
top10_prob = top_probs[:10].sum().item()
```
第 70–78 行。把前 1/5/10 名的概率累加，看分布集中度。运行看到 Top 1 占 99.2%、Top 5 占 99.9%、Top 10 仍 99.9%，剩下 50247 个 token 分 0.1%——一个极尖的分布。

### generate.py：循环生成

```python
scaled_logits = next_token_logits / temperature
probabilities = torch.softmax(scaled_logits, dim=0)
next_token_id = torch.multinomial(probabilities, 1)
```
第 54–58 行。T 在整个脚本里只出现在这个除法；`multinomial` 按分布抽 1 个，而不是取 max。运行看到每步打印"选了 'xxx' (12.3%) | Top 3: …"；T=0.3 时选中项几乎总在前三，T=1.5 时经常不在。

```python
input_ids = torch.cat([input_ids, next_token_id.unsqueeze(0)], dim=1)
```
第 78 行。把新 token 接到序列尾部，下一轮整段重算。`unsqueeze(0)` 补回 batch 维，否则 `[1,n]` 与 `[1]` 拼不上。运行看到序列长度每步 +1。

```python
if next_token.strip() in [".", "!", "?"]:
```
第 86 行。遇到句末标点就 `break`。运行看到输出常在第一个句号处停——这是脚本的硬规则，不是模型判断"我说完了"。

## 5. 数字与公式速查

| 量 | 值 | 含义/出处 |
|---|---|---|
| GPT-2 参数量 | 1.24 亿 | 原文第三节 |
| 词表大小 V | 50257 | 50000 子词 + 256 字节 + 1 结束符 |
| 单步 logits 维度 | 50257 | `outputs.logits` 最后一维 |
| "Thank you very" | 3 token / [10449, 345, 845] | 原文运行结果 |
| P(` much`) | 99.2% | T=1，原文 |
| Top 10 合计 | 99.9% | 剩余 50247 个共 0.1% |
| LLaMA 词表 | 32000 | 原文第三节 |
| Qwen2 词表 | 151936 | 原文第三节 |
| "Paris" 的排名 | 第 5，约 3% | 原文 "The capital of France is" |
| Temperature 三档 | 0.3 / 1.0 / 1.5 | `generate.py` 默认实验 |
| 概率比 | e^(Δlogit/T) | 由 softmax 相除得到 |
| N token 回答 | N 次前向 | 朴素自回归 |

公式只有两个半：

```
P(wᵢ) = e^(logitsᵢ) / Σⱼ e^(logitsⱼ)
P(wᵢ) = e^(logitsᵢ/T) / Σⱼ e^(logitsⱼ/T)
P₁/P₂ = e^((z₁−z₂)/T)
```

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 手机输入法联想 | 给定前文预测下一个 token | 输入法只看最近几个词、只给 3 个候选、不做全词表归一化；大模型对 50257 类做完整分布，上下文可上千 token |
| 打字机效果 | 逐 token 输出 | 打字机的字早已排好，延迟只是显示；这里每个 token 是当场采样出来的，延迟是真实计算 |
| 所有汽车都烧燃料推活塞 | 底层任务相同，差别在工程 | 汽车是闭环机械循环、有惯性；LLM 每步是独立前向，换一个 token 就换一条计算路径。MoE、RoPE 这类架构差异会改能力，不只是"细节调参" |
| 能力是"预测的副产品" | 翻译/数学/代码 | "副产品"不等于"顺便就有"：数据里必须存在该格式的映射，且规模要够；小模型上这些能力不会涌现 |

## 7. 五个误区

❌ "Temperature 越高模型越有创造力" → ✅ 它只把分布摊平，让低概率 token 有机会被抽到 → 除以正数 T 是单调变换，argmax 与排序都不变；知识量没变，变的是采样方差。

❌ "99.2% 就是 99.2% 的准确率" → ✅ 它只是这一步分布的集中度 → softmax 输出未经校准；高分可能来自训练集里的固定搭配（"Thank you very" → " much"），不是"答对"的概率。

❌ "模型一次性写出整段回答" → ✅ 每个 token 一次前向、逐次拼接 → `outputs.logits` 虽然每个位置都有分布，但生成只取 `[-1]`，其余位置只在训练时提供监督。

❌ "T 调到 0 就等于删掉其他词" → ✅ 其他词概率趋近 0 但仍在词表里 → 只有 Δ/T 足够大才会数值下溢；真正的"只留一个"是 argmax，不是 T=0。

❌ "对话能力是单独训练的模块" → ✅ 它是 next token prediction 在对话模板下的表现 → 模型看到的是 `<|user|>…<|assistant|>`，任务是补全 `<|assistant|>` 之后的内容，没有额外的"回答器"。

## 9. 自测 8 题（含答案要点）

1. **logits 和概率的区别？** 答：logits 是未归一化实数，可负、和不为 1；概率是 softmax 后的非负、和为 1 的向量。模型本体只产出 logits。
2. **为什么除以 T 能控制随机性？** 答：P₁/P₂=e^(Δ/T)。T 小则比值放大、分布变尖；T 大则比值趋近 1、分布变平。
3. **为什么生成 30 个 token 要 30 次前向？** 答：没有可写回的内部状态，新 token 只能拼到输入上；KV Cache 只复用中间结果，不改变"每步一次前向"。
4. **argmax 与 multinomial 怎么取舍？** 答：argmax 确定、可复现、易重复退化；multinomial 多样、不可复现。T→0 的极限等价于 argmax。
5. **50257 由什么构成？** 答：50000 个学出来的子词 + 256 个基础字节 + 1 个结束符。
6. **为什么说"回答"不是独立能力？** 答：训练语料里问答以固定模板共现，模型学的是模板后的续写；没有单独的"回答模块"。
7. **对 logits [3, 2, 1] 做 softmax（T=1）。** 答：e³=20.0855、e²=7.3891、e¹=2.7183，Σ=30.1929，概率为 66.52% / 24.47% / 9.00%。
8. **同一组 logits，T=0.5。** 答：z=[6,4,2]，e^z=[403.43, 54.60, 7.389]，Σ=465.42，概率为 86.68% / 11.73% / 1.59%。top1 从 66.5% 升到 86.7%，末位从 9.0% 压到 1.6%。

## 10. 一页速记

- 唯一原语：P(next token | context)。
- 一次前向只为最后一个位置产出可用的下一个分布。
- logits 无约束，softmax 才归一化。
- T 改陡峭度，不改排序。
- 概率比 = e^(Δlogit/T)。
- 生成 = 拼接 + 重算的循环。
- 打字机效果是真实计算，不是动画。
- 对话、翻译、数学都是续写。
- 词表固定，分类类别数固定。
- 采样是"每次不一样"的唯一来源。
- Greedy 稳定但会复读，采样多样但不可复现。

**三个关键数字**：50257（词表与分类类别数）、99.2%（" much" 的概率）、330（logit 差 5.8 时的赔率）。
