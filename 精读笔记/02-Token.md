# 第 2 篇精读｜Token——大模型眼中的"字"长什么样

> 原文：llm-02-token.md ｜ 前置：第 1 篇 ｜ 核心一句话：Token 是分词器输出的整数 ID，是人类文本与模型词表之间那层不可逆的翻译。

## 0. 三句话抓住它

- Token 不是词，也不是字符，是词表里的一个行号。
- BPE 从 256 个字节出发，反复合并最高频相邻对。
- 分词层同时决定了成本、速度、上下文容量和模型的"视力"。

## 1. 这一篇在补哪个洞

第一篇结尾停在 `tokenizer.encode` 这一行：三个英文单词变成 `[10449, 345, 845]`，模型看到的是三个整数。那句"下一篇打开第一个黑盒"指的就是这里——整数是怎么来的。

本篇要补的洞有三个具体问题：token 到底是个什么单位？50257 这个数字凭什么定在这里？为什么同一句话用中文写会更贵？

答案会改写你对"模型能力"的解释。数不对 strawberry 里的 r、中文 token 是英文的两三倍、长文档更容易被截断，这些都不是智力问题，而是分词层的直接后果。Token 是整条链路的起点，它决定了模型能看到什么、看不到什么，也决定了你按 token 付的钱买到了多少信息。

## 2. 概念逐层拆

### 2.1 Token

**是什么**：分词器输出的最小单位，对应词表里的一个整数 ID。

**为什么需要**：神经网络只接受整数索引再查表，不能直接吃字符串；必须先把变长文本压成固定词表上的符号序列。

**在系统里的位置**：输入端第一环；输出端 softmax 的分类类别也是它。

**记住这个数**：GPT-2 的 "Thank you very" = 3 个 token。

### 2.2 Vocabulary（词表）

**是什么**：token 与 ID 的固定双射表，大小 V 在训练开始前就定死。

**为什么需要**：输出层是一个 V 类分类器，维度必须与词表一致；词表一改，所有权重作废。

**在系统里的位置**：`encode` 与 `softmax` 共用同一张表，一头一尾。

**记住这个数**：GPT-2 的 50257 = 50000 个学出的子词 + 256 个字节 + 1 个结束符。

### 2.3 BPE（Byte Pair Encoding，字节对编码）

**是什么**：从单字节词表开始，反复把语料中最高频的相邻对合并成新 token，直到词表达到目标大小。

**为什么需要**：收全部词不可行（词无穷多），只收 256 个字节效率极低（一个汉字要 3 个 token）；BPE 用频率在两者之间找折中。

**在系统里的位置**：训练前的离线预处理，只跑一次；推理时按已学到的合并规则顺序重放。

**记住这个数**：50257 − 256 − 1 ≈ 5 万次合并。

### 2.4 Byte-level BPE（字节级 BPE）

**是什么**：先把文本转成 UTF-8 字节序列，再在字节上跑 BPE；256 个基础字节保证任何字符都能表示。

**为什么需要**：字符级 BPE 遇到未登录字符只能吐 `<unk>`；字节级永远不会 OOV，代价是稀有文字被切得很碎。

**在系统里的位置**：分词器底座，直接决定了中文在 GPT-2 里为什么是"字节碎片"。

**记住这个数**：一个汉字 UTF-8 占 3 字节，"你好"共 6 字节。

### 2.5 Subword（子词）

**是什么**：介于字符和词之间的片段，可能是一个完整词、半个词，也可能只是一个字节。

**为什么需要**：固定词表要覆盖无限文本，只能让高频片段独立成词、低频词现场拼装。

**在系统里的位置**：分词输出，模型实际看到的最小语义单位。

**记住这个数**："Kubernetes" → 4 个 token；"strawberry" → 3 个 token。

### 2.6 Special Token（特殊 token）

**是什么**：不对应自然语言、手工加进词表的控制符号，如 `<|endoftext|>`、`<|user|>`、`<|assistant|>`。

**为什么需要**：模型需要一个可学习的"轮到谁说话""说完了"的信号，纯文本里没有这种边界。

**在系统里的位置**：输入端由 chat template 插入，输出端由模型自己预测。

**记住这个数**：GPT-2 词表里那 1 个特殊符就是结束符。

### 2.7 Token Efficiency（token 效率）

**是什么**：表达同一段信息所需的 token 数，越少越省。

**为什么需要**：费用、延迟、上下文容量全部按 token 计，不按字数计。

**在系统里的位置**：分词层的下游后果，贯穿计费、推理和上下文管理。

**记住这个数**：GPT-2 下中文 token 数是英文的 2–3 倍。

## 3. 手算推演

### 3.1 语料与初始状态

用原文 3.2 的语料：`low low low low low lower lower newest newest newest widest`。

| 词 | 频次 | 字符数 |
|---|---|---|
| low | 5 | 3 |
| lower | 2 | 5 |
| newest | 3 | 6 |
| widest | 1 | 6 |

合计 11 个词、49 个字符；去重后初始词表 10 个：`{l, o, w, e, r, n, s, t, i, d}`。按正文口径，词尾不加 `</w>` 标记（第 4 节会说明代码在这里的差异）。

### 3.2 第 1 轮

所有相邻对的加权计数（词频 × 每词内出现次数）：

| 相邻对 | 次数 | 来自 |
|---|---|---|
| (l, o) | 7 | low×5 + lower×2 |
| (o, w) | 7 | low×5 + lower×2 |
| (w, e) | 5 | lower×2 + newest×3 |
| (e, s) | 4 | newest×3 + widest×1 |
| (s, t) | 4 | newest×3 + widest×1 |
| (n, e) | 3 | newest×3 |
| (e, w) | 3 | newest×3 |
| (e, r) | 2 | lower×2 |
| (w, i) | 1 | widest |
| (i, d) | 1 | widest |
| (d, e) | 1 | widest |

最高频是 7，但 (l, o) 和 (o, w) 打平。平票规则：先被插入计数器的赢。语料从 "low" 开始扫描，先遇到 (l, o)，所以合并 **(l, o) → "lo"**。

合并后分词状态：`lo|w` ×5、`lo|w|e|r` ×2、`n|e|w|e|s|t` ×3、`w|i|d|e|s|t` ×1。词表 10 → **11**。

### 3.3 第 2 轮

| 相邻对 | 次数 |
|---|---|
| (lo, w) | 7 |
| (w, e) | 5 |
| (e, s) | 4 |
| (s, t) | 4 |
| (n, e) | 3 |
| (e, w) | 3 |
| (e, r) | 2 |
| (w, i) / (i, d) / (d, e) | 各 1 |

(lo, w) 7 次，独占第一，合并 **"lo" + "w" → "low"**。分词状态：`low` ×5、`low|e|r` ×2、其余不变。词表 **12**。

### 3.4 第 3 轮

| 相邻对 | 次数 |
|---|---|
| (e, s) | 4 |
| (s, t) | 4 |
| (n, e) | 3 |
| (e, w) | 3 |
| (w, e) | 3 |
| (low, e) | 2 |
| (e, r) | 2 |
| (w, i) / (i, d) / (d, e) | 各 1 |

(e, s) 和 (s, t) 都是 4，又是平票；(e, s) 在 newest 里先出现，所以合并 **(e, s) → "es"**。分词状态：`low` ×5、`low|e|r` ×2、`n|e|w|es|t` ×3、`w|i|d|es|t` ×1。词表 **13**。

### 3.5 三轮之后

| 轮 | 合并对 | 次数 | 新 token | 词表大小 |
|---|---|---|---|---|
| 1 | (l, o) | 7 | lo | 11 |
| 2 | (lo, w) | 7 | low | 12 |
| 3 | (e, s) | 4 | es | 13 |

再跑四轮，走势与原文一致：

| 轮 | 合并对 | 次数 | 新 token | 词表大小 |
|---|---|---|---|---|
| 4 | (es, t) | 4 | est | 14 |
| 5 | (n, e) | 3 | ne | 15 |
| 6 | (ne, w) | 3 | new | 16 |
| 7 | (new, est) | 3 | newest | 17 |

第 5 轮 (n,e)、(e,w)、(w,est) 三个都是 3；第 6 轮 (ne,w) 与 (w,est) 都是 3，仍由插入顺序决定。这说明一件事：**BPE 的输出依赖平票规则，不同实现可以给出不同词表，而每个词表都"正确"。**

用这 7 轮规则切词：

| 输入 | 结果 | token 数 | 说明 |
|---|---|---|---|
| low | [low] | 1 | 高频，完整保留 |
| lower | [low, e, r] | 3 | 再跑 2 轮（lowe、lower）才收成 1 个 |
| newest | [newest] | 1 | 第 7 轮刚合完 |
| widest | [w, i, d, est] | 4 | 低频，但 est 被识别 |
| lowest（未见） | [low, est] | 2 | 两个已知片段现拼 |
| newer（未见） | [new, e, r] | 3 | 只有 new 命中 |
| slower（未见） | [s, low, e, r] | 4 | slow 不在词表，只能借 low |

### 3.6 "你好"到底几个 token、几个字节

- 字符数：2 个汉字。
- 字节数：UTF-8 下"你"= E4 BD A0，"好"= E5 A5 BD，共 **6 字节**。
- GPT-2 分词结果：`[19526, 254, 25001, 121]`，共 **4 个 token**。
- 平均：6 ÷ 4 = **1.5 字节/token**。对照 "Hello"：5 字节、1 个 token，即 5 字节/token，效率差 3.3 倍。
- 换算：3000 汉字的文档 = 9000 字节，按同比例约 9000 ÷ 1.5 = **6000 token**；按 `token_cost.py` 的标准档 $0.005/1k 计算，单次输入 $0.03。同等信息量英文按原文 3.0x 折算约 2000 token，$0.01。

注意 4 个 token 不等于 4 个字节：BPE 允许一个 token 覆盖多个字节，所以"token 数"和"字节数"是两套刻度。原文对"1 汉字几个 token"有两处口径（开头 1–2、4.2 节 GPT-2 行 2–3），差异来自用字构成：常用词多则偏低，生僻字多则偏高；"你好"实测 2.0，正好在区间内。

第 110 行。对新词分词时，按学到的规则**顺序重放**，顺序不能乱；先学到的子词优先。运行看到 `lowest → [low, est]`、`newer → [new, e, r]`。

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 人与模型之间的"翻译层" | 分词器把文本转成 ID | 翻译通常可逆且保义；分词不可逆（空格、规范化会丢），也不保义（token 内部的字符对模型不可见） |
| 固定大小的字典 | 词表容量必须事先定死 | 字典是人按词编的；BPE 词表是频率合并出来的，里面大量是无意义的字节片段 |
| 模型的智力受限于视力 | 分词粒度限制字符级操作 | 不是硬上限：模型可以写代码或分步拼字母绕过；差距主要体现在一次性直觉任务上 |
| BPE 的结果"恰好和语言学吻合" | est 被识别为后缀 | 统计副产品也可能是假象：代码里 `est` 先和词尾标记粘成 `est</w>`，说明合并单位是符号而非词素，"后缀"只是语料里碰巧高频 |
| JSON 给人看，特殊 token 给模型看 | chat template 的角色边界 | 特殊 token 因模型而异，同一段 messages 换模型必须重新模板化，ID 不能跨模型复用 |

## 7. 五个误区

❌ "一个 token 就是一个词" → ✅ 可能是词、子词或单个字节 → BPE 只按频率切，"Kubernetes" 因此变成 4 段。

❌ "中文和英文一样贵" → ✅ GPT-2 下中文 token 数是英文的 2–3 倍 → 词表主要从英文语料学出来，中文分到的位置少、切得碎。

❌ "token 数约等于字数" → ✅ 英文约 1 token ≈ 0.75 词，中文 1 字约 2 token（GPT-2，随用字浮动） → 只能按语言和模型实测，不能拿字数硬套。

❌ "换个模型，token ID 还能接着用" → ✅ 词表和模型绑定，同一 ID 在不同模型里含义不同 → 10449 只在 GPT-2 里是 "Thank"，换 tokenizer 就是另一个符号。

❌ "BPE 懂词法，所以能切出后缀" → ✅ 它只数频率，不懂任何语言学 → "est" 是高频的巧合；换个语料或加个词尾标记，合并顺序和边界就全变。

## 9. 自测 8 题（含答案要点）

1. **Token 和词、字符的区别？** 答：词是语言学单位，字符是书写单位；token 是词表里的条目，可能是整词、半词或一个字节，由 BPE 按频率决定。
2. **为什么词表大小必须固定？** 答：输出层是 V 类分类器，权重矩阵的形状由 V 决定；词表变了，Embedding 和 LM Head 全部失效。
3. **BPE 的起点和停止条件？** 答：起点是 256 个单字节；每轮合并最高频相邻对；直到词表达到目标大小或没有可合并的对。
4. **为什么中文在 GPT-2 下更贵？** 答：词表以英文语料为主，中文常见词没占到独立条目，只能退化成字节碎片，1 个汉字约 2 个 token。
5. **特殊 token 与普通 token 的差别？** 答：普通 token 来自 BPE；特殊 token 是手工加入的控制符号，用于标记角色、轮次和结束，不承载自然语言。
6. **为什么模型数不清 strawberry 里的 r？** 答：它看到的是 `[st, raw, berry]` 三个 token，token 内部的字符结构不在它的输入里，字符级计数不是它的原生操作。
7. **本篇语料第 4 轮合并什么？合并后词表多大？** 答：第 3 轮后 (es,t) 出现 4 次（newest×3 + widest×1），合并为 `est`；词表从 13 增到 14。
8. **3000 汉字的文档，按本篇测得的比例是多少 token、多少钱？** 答：3000 × 3 = 9000 字节；9000 ÷ 1.5 = 6000 token；按 $5/百万 token 计，6000 × 5 ÷ 10⁶ = $0.03。

## 10. 一页速记

- Token 是最小阅读单位，不是词。
- 词表固定，ID 只是行号，没有语义。
- BPE = 从 256 字节开始，合并最高频相邻对。
- 高频完整保留，低频切碎现拼。
- 词表大小 = 合并次数 + 256 + 特殊符。
- 平票时先出现的对赢，所以实现之间会有差异。
- 中文在 GPT-2 下 1 字约 2 token。
- "你好" 6 字节、4 token，平均 1.5 字节/token。
- 特殊 token 是控制信号，不是自然语言。
- 成本、延迟、上下文都按 token 计。
- Token 内部的字符，模型看不见。
- 换模型必须换 tokenizer。
