# 第 3 篇精读｜Embedding——把文字变成数学

> 原文：llm-03-embedding.md ｜ 前置：第 2 篇 ｜ 核心一句话：Embedding 把 token 从行号换成坐标，让语义关系变成高维空间里的几何关系，但它只是起点。

## 0. 三句话抓住它

- Embedding 是查表不是计算，ID 换成一串 d 维实数。
- 语义相似看 cos：方向承载语义，长度不承载。
- 初始向量一词一义，上下文语义靠 Transformer 逐层改写。

## 1. 这一篇在补哪个洞

第二篇结尾留了一个问题："France" 和 "Paris" 编号差很远，模型却知道它们有关系？

上一篇把文本压成了整数 ID，但 ID 只是行号。你没法拿 10449 和 345 做加法，也没法从两个整数的差里读出"国家"和"首都"。模型需要一种表示，让语义相近的词在数学上也接近。

本篇补的就是这一步：怎么把符号变成可计算的坐标。它要回答三个具体问题：为什么实现是"查表"而不是"算出来"？度量相似为什么用 cos 而不是欧氏距离？一个词只有一个向量，遇到一词多义怎么办？

答案分两半：Embedding 负责"你是谁"，Transformer 负责"你在这里是什么意思"。这一篇只做完前半段，但已经把输入端到第一层之间的路铺平了。

## 2. 概念逐层拆

### 2.1 Embedding（嵌入）

**是什么**：把离散 token 映射为 d 维稠密实向量的表示，写作 E(token_id)=W_e[token_id]。

**为什么需要**：整数 ID 之间没有距离概念，网络无法从中提取"猫像狗、不像手机"这类关系；稠密向量让语义比较变成点积和范数。

**在系统里的位置**：输入端第一层，查表得到向量，之后进入 Transformer。

**记住这个数**：GPT-2 的 d=768。

### 2.2 Embedding Table（嵌入表）

**是什么**：一个 V×d 的矩阵，行数等于词表大小，一行就是一个 token 的初始向量。

**为什么需要**：把"表示"变成可训练参数；训练时只更新被查到的行，未被查到的行保持初始值。

**在系统里的位置**：模型最底层的参数块，前向时按 ID 做行索引。

**记住这个数**：GPT-2 是 50257×768，共 38,597,376 个参数。

### 2.3 向量维度 d

**是什么**：每个 token 向量的长度，也是整条残差主干的宽度。

**为什么需要**：维度太低，国家/城市/性别/词性这些特征无法线性分开；维度太高，参数和计算量按 d² 涨。

**在系统里的位置**：表的列数；后续所有层都保持同一宽度，否则残差加不回去。

**记住这个数**：GPT-2 768；LLaMA 7B 4096。

### 2.4 Cosine Similarity（余弦相似度）

**是什么**：cos(A,B)=(A·B)/(‖A‖‖B‖)，等于两个向量夹角的余弦。

**为什么需要**：向量模长受词频和训练动态影响，长度不承载语义；cos 把长度除掉，只留方向。

**在系统里的位置**：相似度计算，离线检索、聚类、向量数据库都用它。

**记住这个数**：值域 [−1,1]；原文实测 France-Paris≈0.65、France-cat≈0.24。

### 2.5 语义方向与向量算术

**是什么**：语义关系表现为空间中的稳定平移方向，如 E(king)−E(man)+E(woman)≈E(queen)。

**为什么需要**：如果关系是方向，模型就能对没见过的组合做零样本推断，而不必为每个词对单独存一条规则。

**在系统里的位置**：对 Embedding 表的后处理分析，不在前向计算里；它是观察工具，不是一层网络。

**记住这个数**：国家→首都、动词时态、单复数共享同一类平移。

### 2.6 Contextual Embedding（上下文向量）

**是什么**：同一个 token 在不同句子里，经过 Transformer 后得到的不同向量。

**为什么需要**：初始表一词一向量，"bank" 的银行与河岸查的是同一行，无法区分。

**在系统里的位置**：Embedding 之后，第 1–12 层逐层改写，最后一层才是上下文语义。

**记住这个数**：原文实测两个 "bank" 在 Embedding 层 cos=1.000，最后一层约 0.6。

### 2.7 Positional Encoding（位置编码）

**是什么**：给每个位置分配一个向量，加到 token 向量上：输入 = Token_Embedding + Position_Embedding。

**为什么需要**：查表与位置无关，"狗咬人"和"人咬狗"的三个 token 向量完全相同，模型无法区分语序。

**在系统里的位置**：输入端，Embedding 之后、进入第一层之前。

**记住这个数**：GPT-2 的 `wpe` 是 1024×768，所以最多 1024 个位置。

## 3. 手算推演

下面 7 个向量是手写的 4 维示意值，不是从 checkpoint 读出来的；目的是让每一步都能验算。4 个维度勉强命名为：d1 国家/制度、d2 城市/地点、d3 男性指向、d4 女性指向。真实模型的维度不可命名，这里只是为了手算。

| 词 | d1 | d2 | d3 | d4 |
|---|---|---|---|---|
| France | 0.90 | 0.10 | 0.10 | 0.10 |
| Paris | 0.55 | 0.80 | 0.05 | 0.05 |
| cat | 0.02 | 0.02 | 0.20 | 0.06 |
| king | 0.10 | 0.10 | 0.85 | 0.05 |
| man | 0.05 | 0.05 | 0.90 | 0.05 |
| woman | 0.05 | 0.05 | 0.05 | 0.90 |
| queen | 0.10 | 0.10 | 0.05 | 0.85 |

### 3.1 France / Paris / cat 两两 cos

**France 与 Paris**

```
F·P = 0.90×0.55 + 0.10×0.80 + 0.10×0.05 + 0.10×0.05
    = 0.495 + 0.080 + 0.005 + 0.005 = 0.585
‖F‖ = √(0.81 + 0.01 + 0.01 + 0.01) = √0.84 = 0.9165
‖P‖ = √(0.3025 + 0.64 + 0.0025 + 0.0025) = √0.9475 = 0.9734
cos = 0.585 / (0.9165 × 0.9734) = 0.585 / 0.8921 = 0.6557
```

**France 与 cat**

```
F·C = 0.90×0.02 + 0.10×0.02 + 0.10×0.20 + 0.10×0.06
    = 0.018 + 0.002 + 0.020 + 0.006 = 0.046
‖C‖ = √(0.0004 + 0.0004 + 0.04 + 0.0036) = √0.0444 = 0.2107
cos = 0.046 / (0.9165 × 0.2107) = 0.046 / 0.1931 = 0.2382
```

**Paris 与 cat**

```
P·C = 0.55×0.02 + 0.80×0.02 + 0.05×0.20 + 0.05×0.06
    = 0.011 + 0.016 + 0.010 + 0.003 = 0.040
cos = 0.040 / (0.9734 × 0.2107) = 0.040 / 0.2051 = 0.1950
```

| 词对 | 点积 | ‖A‖ | ‖B‖ | 分母 | cos |
|---|---|---|---|---|---|
| France-Paris | 0.585 | 0.9165 | 0.9734 | 0.8921 | **0.6557** |
| France-cat | 0.046 | 0.9165 | 0.2107 | 0.1931 | **0.2382** |
| Paris-cat | 0.040 | 0.9734 | 0.2107 | 0.2051 | **0.1950** |

France-Paris 是 France-cat 的 2.75 倍，方向关系被 cos 放大了。但要注意：三个值全为正，最"不相关"的 Paris-cat 也有 0.195——高维空间里存在共同的基线方向，cos 的绝对值不能直接当"语义相似度"，只能看相对排序。

### 3.2 为什么不用欧氏距离

```
‖F−P‖ = √(0.35² + (−0.70)² + 0.05² + 0.05²)
       = √(0.1225 + 0.49 + 0.0025 + 0.0025) = √0.6175 = 0.7858
‖F−C‖ = √(0.88² + 0.08² + (−0.10)² + 0.04²)
       = √(0.7744 + 0.0064 + 0.01 + 0.0016) = √0.7924 = 0.8902
```

欧氏距离只差 13%（0.786 对 0.890），cos 差了 175%（0.656 对 0.238）。原因在模长：cat 的范数只有 0.2107，France 是 0.9165，距离被"短向量"整体压扁了。语义方向的信息被长度噪声盖住，所以检索默认用 cos。

### 3.3 king − man + woman

先做向量加减：

```
R = K − M + W
  = (0.10−0.05+0.05, 0.10−0.05+0.05, 0.85−0.90+0.05, 0.05−0.05+0.90)
  = (0.10, 0.10, 0.00, 0.90)
‖R‖ = √(0.01 + 0.01 + 0 + 0.81) = √0.83 = 0.9110
```

再对词表逐行算 cos，取最近邻：

| 候选 | R·候选 | ‖候选‖ | 分母 | cos |
|---|---|---|---|---|
| queen | 0.785 | 0.8631 | 0.7864 | **0.9983** |
| woman | 0.820 | 0.9042 | 0.8237 | 0.9955 |
| cat | 0.058 | 0.2107 | 0.1920 | 0.3021 |
| France | 0.190 | 0.9165 | 0.8350 | 0.2275 |
| Paris | 0.180 | 0.9734 | 0.8868 | 0.2030 |
| king | 0.065 | 0.8631 | 0.7864 | 0.0827 |
| man | 0.055 | 0.9042 | 0.8237 | 0.0668 |

最近邻是 queen，类比成立。但看 margin：0.9983 − 0.9955 = **0.0028**，只赢了 0.28 个百分点。原因是 R 在 d1/d2 上各带 0.10 的"制度/皇室"分量，正好对上 queen 的 0.10；woman 这两维只有 0.05。但这 0.05 的差只占向量长度的一小部分，cos 对小幅共享分量不敏感。这就是原文说"GPT-2 的 Embedding 层类比准确率有限"的几何解释。

再验证"方向"这件事：

```
W − M = (0, 0, −0.85, 0.85)
Q − K = (0, 0, −0.80, 0.80)
cos(W−M, Q−K) = 1.000
```

两个差向量严格平行，长度比 0.85:0.80——"性别方向"在同一空间里被复用了。真实模型不会这么干净，各语义维度会互相渗透，cos 通常在 1 以下。

最后一个反直觉的数：cos(king, queen)=0.141，比 France-cat 的 0.238 还低。因为 cos 量的是"共享分量占比"，king 与 queen 各自把大部分长度压在相反的性别轴上。语义相关 ≠ 向量夹角小，这是 cos 的边界。

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 身份证号 | token ID 只是索引，不含语义 | 身份证前 6 位含行政区划，其实能读出信息；token ID 完全任意，10449 不含任何"Thank 性" |
| "萌度 / 机械感"两维坐标 | 用特征分数把词画进坐标系 | 真实 768 维没有可命名的单维；2 维图能聚类是降维后的视觉效果，不代表原始维度可读 |
| 拼图 | 把词嵌进有逻辑关系的空间 | 拼图有唯一正确位置；Embedding 是训练得到的局部最优，换语料或随机种子会变，且一个 token 只有一个初始位置 |
| 找邻居 | 语义近则向量近 | 邻居里常混进高频虚词，反义词也可能很近；"近"是共现统计，不等于同义 |
| 起点 / 终点 | 初始向量与上下文向量 | 不是原地修改同一个向量；每层产生新向量并残差叠加，"改写"容易被误解为编辑 |

## 7. 五个误区

❌ "Embedding 的每一维都有明确含义" → ✅ 分布式表示，单维不可命名 → 语义分散在所有维度的组合里；PCA 能聚类只说明整体结构有组织，不代表某一维等于"国家"。

❌ "cos 相似度高就是同义词" → ✅ 它只度量方向重合 → 反义词、同领域词、高频虚词都可能很高；本文例子里 king 与 queen 只有 0.141，比 France-cat 还低。

❌ "一个词永远只有一个向量" → ✅ 初始表固定，最后一层随上下文变 → bank 从 1.000 降到约 0.6，分工是 Embedding 给身份、Transformer 给语境义。

❌ "Embedding 表就是模型的知识库" → ✅ 它只占 GPT-2 参数的 31%、LLaMA 7B 的 1.9% → 知识主要分布式地存在 Attention 和 FFN 的权重里；"开源权重"开的是全部参数。

❌ "向量算术总是成立" → ✅ 它只是统计趋势，初始层经常翻车 → 本例 queen 只赢 woman 0.0028，换个词序或换层就可能输；要看 top-k 和深层表示。

## 9. 自测 8 题（含答案要点）

1. **为什么 token ID 不能直接参与计算？** 答：ID 是任意分配的索引，整数大小和差值没有语义；网络需要的是稠密向量上的点积、范数这类运算。
2. **Embedding 表的大小由什么决定？** 答：V×d。V 是词表大小，d 是隐藏维度；两者都在训练前定死，表是模型参数的一部分。
3. **为什么用 cos 而不是欧氏距离？** 答：模长受词频和训练动态影响，不承载语义；cos 归一化掉长度，只比较方向，抗尺度差异。
4. **"一个词一个向量"哪里不够？** 答：无法表达一词多义；bank 的银行/河岸查到同一行，必须靠后续层结合上下文改写。
5. **位置编码解决什么问题？GPT-2 怎么做？** 答：让模型区分语序；GPT-2 用可学习的 1024×768 位置表，与 token 向量逐元素相加。
6. **为什么"开源权重"不等于"开源 Embedding"？** 答：开源的是全部参数；Embedding 只是其中一块（GPT-2 31%、LLaMA 7B 不到 2%），大头在 Attention 与 FFN。
7. **用本篇向量算 cos(king, queen)。** 答：K·Q = 0.01+0.01+0.0425+0.0425 = 0.105；‖K‖=‖Q‖=√0.745=0.8631；分母 0.7450；cos=0.1409。它比 France-cat 还低，说明 cos 量的是共享分量，不是语义相关度。
8. **算 R=king−man+woman 的模，以及 queen 对 woman 的领先幅度。** 答：R=(0.1, 0.1, 0, 0.9)，‖R‖=√0.83=0.9110；cos(R,queen)=0.785/(0.9110×0.8631)=0.9983；cos(R,woman)=0.82/(0.9110×0.9042)=0.9955；领先 0.0028。

## 10. 一页速记

- ID 是行号，向量才是坐标。
- Embedding 只有查表，没有计算。
- 表大小 = 词表 V × 维度 d。
- 语义相近 = 方向相近，不是长度相近。
- cos ∈ [−1,1]，只看夹角。
- cos 的绝对值有基线，不能当概率。
- 一个 token 一个初始向量。
- 上下文向量由 Transformer 逐层改写。
- bank 从 1.000 降到约 0.6。
- 位置编码让语序进入向量。
