# 第 6 篇精读｜训练：70 亿个参数是怎么"学"出来的

> 原文：llm-06-training.md ｜ 前置：第 5 篇 ｜ 核心一句话：训练就是对 next-token 交叉熵做梯度下降，前向、算 Loss、反向、更新，重复几万亿次。

## 0. 三句话抓住它

- 训练不灌输知识，只把下一个词的交叉熵往下压。
- 全部算法四步：前向、算 Loss、反向传播、更新参数。
- 7B 模型训练显存超 100GB，一张 80GB 的 A100 装不下。

## 1. 这一篇在补哪个洞

第五篇把整机拆完了：12 层、1.244 亿个参数、从 token ID 到 50,257 个 logits 的完整通路。但那张图上所有数字都还只是**形状**，没有一个具体取值。初始化时它们是随机的，问模型 "Thank you very" 后面是什么，50,257 个 token 的概率几乎一样平。

本篇要回答的是：**这些随机数凭什么变成有用的数？** 更准确地说，是什么目标函数、什么信号、按什么规则、更新多少次，才让 "much" 的概率从 1/50,257 涨到 0.992。

答案朴素得有点意外：没有第二条学习规则，全部参数共享同一个训练信号——预测下一个 token。搞懂这一篇，你就能判断市面上关于"微调""对齐""蒸馏"的说法哪些是真机制、哪些只是营销词。

## 2. 概念逐层拆

### 交叉熵 Loss（Cross-Entropy Loss）

**是什么**：`Loss = -log P(正确答案)`，对正确 token 的预测概率取负对数。
**为什么需要**：需要一个标量来衡量"猜得多离谱"，才能对 70 亿个参数求导；用 0/1 准确率无法求导。
**在系统里的位置**：前向的最末端，计算环节，是整个训练的唯一优化目标。
**记住这个数**：随机初始化时 P≈1/50,257，Loss≈10.8；训练好后 P=0.992，Loss≈0.008。

### 梯度（Gradient）

**是什么**：Loss 对每个参数的偏导数，指向"Loss 上升最快的方向"。
**为什么需要**：70 亿个参数无法靠试错逐个搜索，梯度一次性给出每个旋钮的方向和敏感度。
**在系统里的位置**：反向传播的产出，计算环节，形状与参数完全相同。
**记住这个数**：一个 7B 模型的梯度本身就有 7×10⁹ 个数，float32 下 28GB。

### 反向传播（Backpropagation）

**是什么**：从 Loss 出发，用链式法则把梯度逐层往回乘，一路传到 Embedding。
**为什么需要**：朴素求导要每个参数单独扰动一次，7B 参数就要 70 亿次前向，完全不可行。
**在系统里的位置**：`loss.backward()` 触发的计算环节，方向与前向相反，中间激活值必须留着供它使用。
**记住这个数**：一次前向 + 一次反向的算力约是纯前向的 3 倍，这是"训练比推理贵"的根源。

### 学习率与梯度下降

**是什么**：`新参数 = 旧参数 − lr × 梯度`。
**为什么需要**：梯度只给方向，必须有一个步长把连续优化变成可执行的迭代。
**在系统里的位置**：`optimizer.step()`，参数更新环节，是唯一真正改写权重的地方。
**记住这个数**：大模型常用 1e-4 量级；本文微型模型用 3e-3，因为模型小、步子可以大。

### 优化器（AdamW）

**是什么**：在梯度下降上加一阶动量与二阶动量，并为每个参数维护自适应的步长。
**为什么需要**：纯 SGD 在参数尺度差异巨大时会被少数大梯度维度主导，收敛极慢。
**在系统里的位置**：`optimizer.step()` 内部，运行时还要额外存两份状态。
**记住这个数**：Adam 每个参数要存 m 和 v 两份 float32，7B 模型就是 56GB。

### batch / step / epoch

**是什么**：batch 是一次前向用的样本数，step 是一次参数更新，epoch 是把数据集完整过一遍。
**为什么需要**：单样本梯度噪声太大，全量梯度又太贵，mini-batch 是折中。
**在系统里的位置**：数据加载环节，决定 GPU 利用率和梯度质量。
**记住这个数**：本文 `seq_len=32, batch_size=8`，一个 step 只看 256 个字符。

### 三阶段：Pre-training / SFT / RLHF

**是什么**：预训练学语言与知识，SFT 学"问答格式"，RLHF 学"哪种回答更受欢迎"。
**为什么需要**：预训练完的模型只会续写网页，你提问它也不回答，直接生成下一段文本。
**在系统里的位置**：训练流程的三个串行阶段，前两阶段目标函数相同，第三阶段换成奖励信号。
**记住这个数**：预训练 1–15 万亿 token，SFT 几万条对话，RLHF 几万条偏好，量级差 8 个数量级。

### 显存四件套

**是什么**：参数、梯度、优化器状态、激活值，四样都要驻留显存。
**为什么需要**：只算参数会低估 4 倍以上，直接导致 OOM 或训练方案设计错误。
**在系统里的位置**：工程约束，决定并行策略与能否单卡跑。
**记住这个数**：7B 模型 28+28+56 = 112GB，加激活值远超 100GB。

## 3. 手算推演

玩具模型：`ŷ = w·x + b`，只有一个输入 `x = 2`，真值 `y = 5`，初始 `w = 1, b = 0`，学习率 `lr = 0.05`，Loss 用 MSE：`L = (ŷ − y)²`。

**第 0 轮，初始状态。**
前向：ŷ = 1 × 2 + 0 = **2.0**。
误差：ŷ − y = 2 − 5 = **−3.0**。
Loss：L = (−3)² = **9.0**。

**第 1 轮，求导。**
先对输出求导：∂L/∂ŷ = 2(ŷ − y) = 2 × (−3) = **−6.0**。
再对 w 求导，链式乘上 ∂ŷ/∂w = x = 2：∂L/∂w = −6 × 2 = **−12.0**。
再对 b 求导，∂ŷ/∂b = 1：∂L/∂b = −6 × 1 = **−6.0**。

**第 1 轮，更新。**
w = 1 − 0.05 × (−12) = 1 + 0.6 = **1.6**。
b = 0 − 0.05 × (−6) = 0 + 0.3 = **0.3**。
梯度是负的，减去负数等于加上去，参数朝增大方向走——因为当前预测 2 比真值 5 小，确实该往上调。

**第 2 轮，重新前向。**
ŷ = 1.6 × 2 + 0.3 = 3.2 + 0.3 = **3.5**。
误差 = 3.5 − 5 = **−1.5**，Loss = (−1.5)² = **2.25**。
Loss 从 9.0 掉到 2.25，正好是原来的 1/4。

**第 2 轮，求导与更新。**
∂L/∂ŷ = 2 × (−1.5) = −3.0。
∂L/∂w = −3.0 × 2 = **−6.0** → w = 1.6 + 0.05 × 6 = **1.9**。
∂L/∂b = −3.0 × 1 = **−3.0** → b = 0.3 + 0.05 × 3 = **0.45**。

**第 3 轮，验证收敛趋势。**
ŷ = 1.9 × 2 + 0.45 = **4.25**，Loss = (−0.75)² = **0.5625**。
∂L/∂w = 2 × (−0.75) × 2 = −3.0 → w = 1.9 + 0.15 = **2.05**。
∂L/∂b = 2 × (−0.75) = −1.5 → b = 0.45 + 0.075 = **0.525**。
第 4 轮预测 ŷ = 2.05 × 2 + 0.525 = **4.625**，Loss = **0.140625**。

Loss 序列：9 → 2.25 → 0.5625 → 0.140625，每步除以 4。原因是这个线性模型的 Hessian 恰好让 lr=0.05 落在稳定区间，误差按固定比例收缩。真实网络不会这么规整，但"先快后慢、指数下降"的形状是一致的。

**一个口径提醒**：如果 Loss 定义成 `½(ŷ−y)²`，所有梯度会少乘 2，第 1 轮 w 只走到 1.3。所以看别人的推导时，先确认 MSE 有没有那个 1/2，否则数值对不上。

## 4. 代码逐行

`train_tiny.py`，纯 PyTorch，无 transformers 依赖，CPU 几分钟跑完。

```python
ix = torch.randint(0, len(data) - seq_len - 1, (batch_size,))
x = torch.stack([data[i:i+seq_len] for i in ix])
y = torch.stack([data[i+1:i+seq_len+1] for i in ix])
```
随机抽 8 个起点，切出 8 段 32 字符。注意 `y` 是 `x` 整体右移一位——这就是"下一个字符"标签的全部构造方式，没有人工标注。

```python
logits = model(x)
loss = F.cross_entropy(logits.view(-1, vocab_size), y.view(-1))
```
`logits` 形状是 `[8, 32, vocab]`，`view(-1, vocab)` 摊平成 `[256, vocab]`，与 `y` 的 256 个标签一一对应。`cross_entropy` 内部先做 log_softmax 再取负对数，数值上比"先 softmax 再 log"稳定。

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```
三步顺序不能乱：清空上轮梯度 → 反向累积本轮梯度 → 按梯度改参数。原文那段四行代码省略了 `zero_grad()`，实际脚本里有；不清零的话梯度会跨 step 累加，等效于学习率不断变大。

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3)
```
AdamW 把权重衰减与梯度更新解耦。这里 lr 取 3e-3，比大模型的 1e-4 大三十倍，因为模型只有几十万参数、数据只有 500 多个字符，小步走会训不完。

```python
self.lm_head.weight = self.token_emb.weight
```
直接赋值让两个 Module 指向同一个 Parameter，这就是第五篇讲的权重共享在代码里的写法。副作用是 `parameters()` 去重后只算一次，所以打印出的参数量不含重复项。

```python
mask = torch.triu(torch.ones(T, T, device=x.device), diagonal=1).bool()
scores = scores.masked_fill(mask.unsqueeze(0).unsqueeze(0), float('-inf'))
```
上三角为 True，即"允许看到未来"的位置被填成负无穷，softmax 之后权重恰好为 0。这是 GPT 类模型能并行训练又不作弊的关键。

运行后能看到 Loss 从 `3.526` 降到 `0.847` 左右，以及"The capital of "能续出 "France is Paris."。Step 0 的 3.526 与 `log(词表大小)` 同一量级——这份语料一共 37 个字符，ln37 ≈ 3.61，说明此时模型基本在均匀瞎猜，差的那 0.08 来自初始化 logits 并不严格相等。

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 70 亿个旋钮的收音机 | 参数空间 | 旋钮彼此独立，神经网络参数强耦合，动一个会改变其余所有人的最优值 |
| 听一下、对答案 | 前向 + 算 Loss | 调台有明确的"清晰度"感官判断，Loss 只是一个代理指标，它降了不代表回答更好 |
| 每个旋钮试转一点 | 数值梯度 | 真实训练用解析梯度一次算全，不是逐个试；逐个试的复杂度是参数量的平方 |
| 多米诺骨牌倒着推 | 反向传播 | 骨牌只有一条链，计算图是 DAG，一个节点可能收到多条回传梯度并相加 |
| 山谷里找最低点 | 梯度下降 | 70 亿维空间不是山谷而是鞍点密布的曲面，"最低点"既找不到也不唯一 |
| 背课文 | 小数据过拟合 | 背课文是逐字记忆，模型记的是统计规律；数据量够大时同一机制就变成"学会语言" |
| 上学读书 / 入职培训 / 师傅带徒弟 | 预训练 / SFT / RLHF | 真人上学同时学知识和规范，这三个阶段是割裂的，RLHF 完全不引入新事实 |

## 7. 五个误区

❌ 训练就是教模型知识 → ✅ 训练是最小化 next-token 交叉熵，知识是副产物 → 因为目标函数里只有"猜对下一个词"，没有任何事实三元组；能答对首都是因为它在语料里反复共现。

❌ Loss 降到 0 就完美了 → ✅ 训练集 Loss 到 0 通常意味着过拟合，泛化反而变差 → 因为模型可以把 500 个字符逐字背下来，遇到没见过的输入仍然输出垃圾。

❌ 学习率越大收敛越快 → ✅ 过大会震荡甚至发散，过小会卡在平台期 → 因为步长超过局部曲率的稳定上限时，每次更新都会跨过谷底并放大误差。

❌ 梯度下降能保证找到全局最优 → ✅ 深度网络非凸，只能收敛到某个表现良好的局部区域 → 因为参数空间维度极高、对称性极强，实践中"好解"比"最优解"更有意义。

❌ SFT 和 RLHF 能给模型灌新知识 → ✅ 它们主要改行为、格式与偏好，事实仍来自预训练 → 因为 SFT 数据只有几万条，覆盖不了知识面；强行灌事实容易变成幻觉式背诵。

## 9. 自测 8 题（含答案要点）

1. 为什么随机初始化时 Loss 约等于 log(词表大小)？
   要点：50,257 个 token 概率近似均匀，正确答案的概率是 1/50,257，−log 之后就是 log(50,257)≈10.8。

2. 为什么用 −log P 而不是 1−P 作为 Loss？
   要点：−log 在 P→0 时趋于无穷，惩罚与离谱程度匹配；1−P 有上界 1，梯度在极度错误时反而变小。而且 −log 的取值范围更适合优化。

3. 反向传播和梯度下降有什么区别？
   要点：反向传播负责**算**梯度，梯度下降负责**用**梯度。前者是链式法则的实现，后者是参数更新规则。

4. 预训练完的模型为什么不会好好回答问题？
   要点：训练语料里问题后面跟的通常是另一段文本而不是回答；模型只学会了"续写得像"，没学过"对话轮次"这种格式。

5. SFT 与 RLHF 各自改变什么？
   要点：SFT 用问答对教格式，目标函数仍是交叉熵；RLHF 先训奖励模型再用它打分，优化的是人类偏好而非某个标准答案。

6. 为什么说数据质量比数量更重要？
   要点：模型会照单全收语料里的错误与偏见；重复内容还会让模型过度记忆。清洗、去重、配比属于核心工艺。

7. 【计算】接本篇手算，从 w=1.9、b=0.45 再走一步，参数与 Loss 变成多少？
   要点：ŷ=4.25，Loss=0.5625；∂L/∂w=−3.0 → w=2.05；∂L/∂b=−1.5 → b=0.525；下一轮 ŷ=4.625，Loss=0.140625。

8. 【计算】按原文口径（参数 4 字节、梯度 4 字节、Adam 状态两份共 8 字节），13B 模型光状态要多少显存？几张 80GB 卡才装得下？
   要点：每参数 16 字节，13×10⁹×16 = 208GB；208÷80 = 2.6，至少要 3 张，且还没算激活值。

## 10. 一页速记

- 训练的唯一信号是"下一个 token 猜得对不对"。
- Loss = −log P(正确 token)，越小越好，没有第二个目标。
- 梯度给方向，学习率给步长，两者相乘就是更新量。
- 反向传播复用前向的中间结果，所以激活值必须留在显存里。
- Adam 的状态是参数的两倍，这是显存账本里最容易被忽略的一项。
- batch 决定梯度噪声，step 决定更新次数，epoch 决定数据被看几遍。
- 三阶段不是三种算法，前两个阶段目标函数完全相同。
- 预训练管"会说话"，SFT 管"会答话"，RLHF 管"答得讨人喜欢"。
- 小数据训练出来的是背课文，大数据训练出来的是统计规律。
- 训练能并行，是因为整段文本的标签可以一次错位构造出来。

三个关键数字：**10.8**（随机初始化的 Loss）、**0.008**（P=0.992 时的 Loss）、**112GB**（7B 模型不含激活值的训练状态）。
