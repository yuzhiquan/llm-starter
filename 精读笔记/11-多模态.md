# 第 11 篇精读｜多模态：大模型是怎么“看懂”图片的

> 原文：llm-11-multimodal.md ｜ 前置：第 10 篇 ｜ 核心一句话：多模态没有换架构，只是在 Transformer 入口接了一条把图片翻译成向量序列的编码器管线。

## 0. 三句话抓住它

- 图片进 Transformer 的唯一通道，是切成 patch 再线性投影成向量。
- 投影层负责把图像向量搬到文本向量所在的空间，这一步决定“看得懂”。
- Attention、FFN、损失函数、KV Cache 全部沿用，改的只有输入端。

## 1. 这一篇在补哪个洞

正篇十篇有一个没明说的前提：输入永远是文本，先过 Tokenizer，再查 Embedding 表。第 2 篇把字符串切成 token，第 3 篇把 token 变成向量，第 4 篇的 Attention 只要求“输入是一串 d 维向量”，第 7 篇的 Prefill/Decode 也默认序列长度按文本 token 数算。这个前提在产品里最先被打破——用户直接甩图，模型必须接住。

这篇番外挂在这条链的入口处，补的是“非文本模态如何进入同一条流水线”。它不引入新架构，只增加两件东西：图像编码器（ViT）和投影层。理解了这一点，正篇第 5 篇的 Transformer 结构图可以原封不动地复用。

现实问题也很直接：一张图会变成几百个 token，直接冲进第 8 篇的上下文窗口和第 7 篇的 KV Cache 账本。多模态不是“加个功能”，而是“给成本模型加了一个高倍率乘数”。读完要能做到：看到一张图，估出它占多少 token、多少显存、贵多少。

## 2. 概念逐层拆

### 2.1 Patch（图像块）

**是什么**：把 H×W×3 的像素矩阵按固定边长切开，每个小方块内的所有像素按通道展平成一个向量。224×224 的图用 16×16 切，得到 14×14 个块。

**为什么需要**：Transformer 的输入长度有限，整图逐像素输入是 150,528 维，Attention 直接爆炸；切成 196 个 768 维向量，长度和维度都进入可控区间。

**在系统里的位置**：位于整条多模态管线最前端，替代了文本侧的 BPE 分词器，是“图像的分词”。

**记住这个数**：16×16×3 = 768，一个 patch 展平后正好 768 维。

### 2.2 ViT（Vision Transformer）

**是什么**：用 Transformer 的编码器结构处理 patch 序列的视觉模型，输出每个 patch 一个上下文向量。

**为什么需要**：CNN 的归纳偏置是局部感受野，而 patch 之间需要全局关系（猫耳朵和沙发要建立联系），自注意力的全连接特性正好合适。

**在系统里的位置**：图像侧的“特征提取器”，它的输出还不属于语言空间，需要后面的投影层转接。

**记住这个数**：ViT-B/16 的隐藏维度是 768，和很多文本模型的 Embedding 维度相同，但这不代表语义空间相同。

### 2.3 Patch Embedding（线性投影）

**是什么**：一个作用在每个 patch 上的线性层 `W ∈ R^{768×768}` 加 bias，把展平像素映射成模型维度。

**为什么需要**：原始像素值（0–255）没有语义，线性层是可学习的基变换，把“颜色块”变成“特征”。

**在系统里的位置**：patchify 之后、位置编码之前，是图像侧唯一与文本 Embedding 表地位对等的参数。

**记住这个数**：768×768 + 768 = 590,592 个参数，不到 0.6M。

### 2.4 位置编码（Position Embedding）

**是什么**：一个可学习矩阵，第 i 行加到第 i 个 patch 向量上，告诉模型这个块在原图的哪一格。

**为什么需要**：Attention 对输入顺序是置换不变的，去掉位置编码，196 个 patch 就退化成一个“词袋”，空间关系全部丢失。

**在系统里的位置**：patch embedding 之后、进入 Transformer 之前，和文本侧的 positional embedding 是同一个角色。

**记住这个数**：196×768 = 150,528 个参数；换到 448×448 要 784×768 = 602,112，多出来的部分必须重新学或插值。

### 2.5 投影层（Projector）

**是什么**：一到两层线性层（原文示例 1024→4096），把视觉编码器的输出维度映射到语言模型的隐藏维度。

**为什么需要**：视觉编码器（如 CLIP ViT）的空间由图文对比或图像分类目标训练，LLM 的空间由下一个词预测训练，两者维度和几何都不同，不能直接拼接。

**在系统里的位置**：图像管线与文本管线的接缝，也是第一阶段训练唯一更新的参数。

**记住这个数**：768→4096 的投影层有 768×4096 + 4096 = 3,149,824 个参数，约 3.15M。

### 2.6 图像 Token

**是什么**：投影层输出的每一个向量，在序列里占一个位置，和文本 token 的向量同权参与 Attention。

**为什么需要**：这是“把图片塞进语言模型”的落地形式——不是把图转成一段文字描述，而是让向量直接排在文本向量后面。

**在系统里的位置**：输入序列的中段或后段；对 KV Cache 来说，它和文本 token 完全一样，每层都要存 K 和 V。

**记住这个数**：224×224 的一张图 = 196 个 token，约等于 196 个汉字量级的占位。

### 2.7 两阶段训练（对齐 + 指令微调）

**是什么**：第一阶段冻结 ViT 和 LLM，只训投影层，用图文配对数据做对齐；第二阶段解冻 LLM，用“看图问答”数据做指令微调。

**为什么需要**：直接联合训练会让语言能力被少量图文数据冲垮；先让翻译器学会对齐，再让大脑学会用眼睛。

**在系统里的位置**：对应正篇第 6 篇的三阶段训练，但把“预训练”换成了“模态对齐”。

**记住这个数**：第一阶段可训练参数只有投影层的约 3M，占 7B 模型的 0.04%。

### 2.8 Cross-Attention（对照概念）

**是什么**：在 Transformer 层间插入专门的模块，让文本位置去查询图像位置，而不是把两者拼在同一条序列里。

**为什么需要**：拼接会让图像 token 占满窗口；交叉注意力可以把图像压成较少的键值对，按需查询。

**在系统里的位置**：LLaVA 这类用拼接，Flamingo 这类用 Cross-Attention；两者都保留原 Transformer 主干。

**记住这个数**：原文口径下 LLaVA 是 196 个图像 token 全量拼接，不做压缩。

## 3. 手算推演

**第一步：数像素。** 224×224×3 = 150,528 个数值。这是图片的“原始长度”。

**第二步：切网格。** 224 ÷ 16 = 14，所以横竖各 14 块，14×14 = **196 个 patch**。

**第三步：验证无损。** 每个 patch 展平是 16×16×3 = **768 维**；196×768 = 150,528，和第一步完全相等。切块没有丢信息，只是换了排列方式。

**第四步：算 patch embedding 参数。** 输入 768 维、输出 768 维，权重 768×768 = 589,824，加 bias 768，共 **590,592** 个参数。

**第五步：算位置编码。** 196 个位置 × 768 维 = **150,528** 个参数。图像侧入口的总参数约 590,592 + 150,528 = 741,120，即 0.74M。

**第六步：换分辨率。** 448×448 时 448 ÷ 16 = 28，网格 28×28 = **784 个 patch**，是 196 的 4 倍；每个 patch 仍是 768 维。位置编码变成 784×768 = 602,112。序列长度 4 倍，Attention 打分矩阵是 n²，所以是 4² = **16 倍**计算量；KV Cache 随 token 数线性增长，是 **4 倍**。

**第七步：算 token 占比。** 一句“请描述这张图片”按原文约 5 个 token，加 196 个图像 token，总长 201。8K 窗口下图像占 196÷8192 = **2.39%**；十张图就是 1,960 token，占 **23.9%**。换成 448×448，一张图 784 token，占 8K 的 **9.57%**。

**第八步：算显存。** 按 32 层、d=4096、fp16、标准多头（非 GQA），每个 token 每层的 K 和 V 是 2×4096 个数，2 字节。单 token 全部层：32×2×4096×2 = 524,288 B = 512 KB。196 个图像 token：196×524,288 = 102,760,448 B ≈ **98 MB**。一张图仅 KV Cache 就接近 100MB，这还没算文本和模型权重。

## 4. 代码逐行

```python
x = img.reshape(3, 224, 224)              # ① 像素张量，150,528 个数
p = x.reshape(3, 14, 16, 14, 16)          # ② 切成 14×14 个 16×16 块
p = p.transpose(1, 3, 0, 2, 4)            # ③ 块排到前面：(14,14,3,16,16)
seq = p.reshape(196, 768)                 # ④ 每个 patch 展平成 768 维
seq = seq @ W_patch + b                   # ⑤ patch embedding，768→768
seq = seq + pos_emb                       # ⑥ 加位置编码，196×768
seq = seq @ W_proj                        # ⑦ 投影到语言空间，768→4096
tokens = concat([text_emb, seq], dim=0)   # ⑧ 文本向量在前，图像向量在后
logits = transformer(tokens)              # ⑨ 与正篇完全相同的 Transformer
next_id = argmax(logits[-1])              # ⑩ 仍然预测下一个 token
```

① 对应“原始输入是像素矩阵”；②③④ 对应 patchify，注意 reshape+transpose 不产生任何参数；⑤ 是 2.3 的线性层；⑥ 是 2.4，缺了它模型分不清左上和右下；⑦ 是 2.5 的投影层，也是唯一跨空间的一步；⑧ 是 2.6，序列拼接而不是模态融合；⑨ 证明第 5 篇的结构一行没改；⑩ 证明训练目标仍是第 1 篇的下一个 token 预测。

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 图片的“翻译器” | 投影层把图像向量译到文本空间 | 翻译是离散、可逆、双向的；投影层是连续、单向、不可逆的，译过去之后没法还原成像素，也不保证语义一一对应 |
| “大脑没变，只是眼睛是新装的” | Transformer 主干不变，只加 ViT+投影 | 结构没变不等于权重没变：第二阶段会解冻 LLM，输入的分布也彻底变了；眼睛装上去，大脑的视觉皮层也被重塑了 |
| 图像也有“token” | 196 个向量占序列位置 | 文本 token 是离散词表 ID，可 detokenize、可数、边界对应子词；图像 token 是连续向量，没有词表、不可还原，一个 patch 也不对应一个语义单位 |
| 把图片“切成碎片” | patchify | 拼图碎片的边界是语义边界，patch 是在物体中间硬切的；模型只能靠 Attention 把被切断的耳朵和身体重新拼起来 |
| 和文本“拼在一起” | concat 后送进同一个 Attention | 拼接会让图像 token 与文本 token 争夺窗口和注意力；真实系统常做池化、重采样或 Cross-Attention，不是无脑全拼 |

## 7. 五个误区

❌ 多模态是另一套架构 → ✅ 主干仍是第 5 篇的 Transformer，只换了入口 → 因为 Attention 只要求输入是向量序列，不关心向量来源。

❌ 图片先被转成一段文字描述再进模型 → ✅ 主流 LLaVA 类做法是视觉向量直接拼接，不经过中间文本 → 因为中间文本会引入信息瓶颈，且描述不了“左上角的第三个小物体”。

❌ patch 切得越细，模型一定看得越清楚 → ✅ 分辨率翻倍 patch 数变 4 倍、注意力变 16 倍，且有效分辨率受训练分布和投影层限制 → 因为模型没见过的高密度 patch 只是更贵的噪声。

❌ 位置编码可有可无，反正 Attention 会学 → ✅ 去掉后 196 个 patch 变成无序词袋，空间关系不可恢复 → 因为标准 Attention 对置换等变，顺序信息必须外部注入。

❌ 图像 token 和文本 token 计费完全一样 → ✅ 位置上等价、算力上同构，但价目表未必单列视觉 token → 原文只给了 DeepSeek V4 的文本单价，没有视觉定价，不能替它编一个数字。

## 9. 自测 8 题（含答案要点）

**概念题**

1. 为什么必须把图片切成 patch，而不能整图压成一个向量？
   **答案要点**：整图压成一个向量丢空间细节，196 个 patch 保留局部信息，再由 Attention 建立全局关系；同时序列长度可控。

2. ViT 输出为什么不能直接拼到文本 Embedding 后面？
   **答案要点**：两个空间由不同目标训练，维度与几何都不一致；需要投影层做维度映射和语义对齐。

3. 位置编码去掉会发生什么？
   **答案要点**：Attention 置换等变，patch 顺序信息丢失，模型无法区分左上与右下，空间结构退化为词袋。

4. 第一阶段为什么要冻结 LLM 和 ViT？
   **答案要点**：只训投影层，参数量约 3M，成本低且不会破坏已有语言能力；先对齐再instruction tuning。

5. Attention 怎么区分文本向量和图像向量？
   **答案要点**：不区分。它只做 Q·Kᵀ/√d → softmax → ·V，来源信息靠位置和训练中学到的模式隐式体现。

6. 一张 448×448 的图比 224×224 贵多少？
   **答案要点**：token 数 4 倍（784 vs 196），注意力计算 16 倍，KV Cache 4 倍。

**计算题**

7. 384×384 的图，patch 仍为 16×16，patch 数、序列长度倍数、注意力矩阵倍数各是多少？
   **答案要点**：384÷16 = 24，24×24 = 576 个 patch；576÷196 = 2.94 倍；576²÷196² = 8.64 倍。

8. 一张 448×448 图加 20 个文本 token，32 层、d=4096、fp16、标准多头，KV Cache 多少？
   **答案要点**：总 token 804；每 token 每层 K+V 为 2×4096×2 B = 16KB；32 层为 512KB；804×524,288 = 421,527,552 B ≈ 402 MiB。

## 10. 一页速记

- 多模态 = 文本模型 + 图像编码器 + 投影层，主干不动。
- 224×224 切 16×16，得到 14×14 = 196 个 patch。
- 每个 patch 展平 768 维，patch embedding 参数 590,592。
- 位置编码 196×768，负责恢复空间关系。
- 投影层把视觉维度搬到语言维度，是唯一跨空间的部件。
- 图像 token 与文本 token 在同一序列里同权参与 Attention。
- 训练仍是下一个 token 预测，分对齐与指令微调两步。
- 448×448 让 token 变 4 倍、注意力变 16 倍。
- 一张 224 图约占 8K 窗口的 2.4%，十张图占近四分之一。
- 单图 KV Cache 约 98MB，图像是显存和成本的高倍乘数。

三个关键数字：**196**（一张图的 token 数）、**768**（单 patch 维度）、**4 倍**（分辨率翻倍后的 token 增长）。
