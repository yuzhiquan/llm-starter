# 第 12 篇精读｜GPU：为什么大模型离不开它

> 原文：llm-12-gpu.md ｜ 前置：第 11 篇 ｜ 核心一句话：大模型的核心是矩阵乘法，它由海量互不依赖的乘加组成，正好是 GPU 几千个弱核心的主场。

## 0. 三句话抓住它

- 矩阵乘法的每个输出元素都能独立计算，天然适合并行。
- Decode 每生成一个 token 要读一遍全部权重，瓶颈是带宽不是算力。
- 显存装不下比算得慢更致命，它直接决定模型能不能跑。

## 1. 这一篇在补哪个洞

正篇讲算法时都隐含一个假设：算力是免费的。第 5 篇拆 Transformer 结构，只关心有几层、几块矩阵；第 6 篇算训练，只关心参数量和梯度；第 7 篇讲 Prefill/Decode，只关心流程；第 9 篇的 Scaling Law 更是直接说“越大越好”。没有一篇回答：这些矩阵乘法落到硅片上要多久、要多少内存、为什么必须是 GPU。

这篇番外补的就是这层硬件约束。它把正篇的“计算量”翻译成两个可测的量：时间和显存。翻译的桥梁是内存带宽——同样的 14GB 权重，从 DDR5 搬到核心要 175ms，从 HBM 搬只要 7ms，差 25 倍，而两者的浮点算力差距远没有这么直观。

现实问题：为什么本地跑 7B 很卡、为什么量化能把模型塞进 24GB、为什么 H100 比 A100 贵那么多、为什么训练要几千张卡而推理一张就够。这些决策全部由本篇的三个量决定：算力、带宽、显存。

## 2. 概念逐层拆

### 2.1 并行度（Parallelism）

**是什么**：同一时刻能独立执行的运算数量。矩阵乘法 C[i][j] 只依赖 A 的第 i 行和 B 的第 j 列，任意两个 C 元素之间没有依赖。

**为什么需要**：只有存在大量独立任务，多核心才有意义；有依赖的运算只能串行，核心再多也只能排队。

**在系统里的位置**：它是 GPU 存在的理由，也是 batch、数据并行、张量并行所有并行策略的物理基础。

**记住这个数**：4096×4096 乘 4096×4096，结果有 16,777,216 个元素，全部可同时算。

### 2.2 SM 与 CUDA Core

**是什么**：GPU 的流式多处理器（SM）是调度单元，里面装着一批 CUDA Core，每个 core 只能做简单的乘加。

**为什么需要**：把“一个复杂核心”换成“几千个简单核心”，在同样芯片面积下能堆出高得多的吞吐。

**在系统里的位置**：矩阵乘法被切成小块（tile）分给 SM，SM 再分给 core；这是 cuBLAS 等库自动完成的。

**记住这个数**：A100 有 108 个 SM、合计 6,912 个 FP32 CUDA Core；原文按 16,384 个并行核心的口径估算吞吐。

### 2.3 算力（FLOPS）

**是什么**：每秒浮点运算次数，衡量“算得多快”。一次乘加算 2 次浮点运算。

**为什么需要**：它决定计算密集型任务（训练、Prefill）的上限。

**在系统里的位置**：与带宽一起构成硬件的两条腿；训练看它，Decode 不看它。

**记住这个数**：A100 约 312 TFLOPS（fp16），H100 约 989 TFLOPS（fp16 稠密），消费级 i9 约 1 TFLOPS。

### 2.4 内存带宽（Memory Bandwidth）

**是什么**：单位时间能从内存搬到计算核心的字节数，单位 GB/s。

**为什么需要**：核心算得再快，数据送不进去就只能空转；大模型每步要搬的正是全部权重。

**在系统里的位置**：Decode 阶段的唯一瓶颈，也是 H100 相对 A100 在推理上最大的优势来源。

**记住这个数**：DDR5 约 80 GB/s，A100 约 2,000 GB/s，H100 约 3,350 GB/s。

### 2.5 算术强度（Arithmetic Intensity）

**是什么**：每搬运 1 字节数据能做多少次浮点运算，单位 FLOP/B。

**为什么需要**：它决定一个任务是算力瓶颈还是带宽瓶颈；低于硬件的“拐点”就是带宽瓶颈。

**在系统里的位置**：判断优化方向的标尺——提高 batch 就是提高算术强度。

**记住这个数**：7B 模型 decode 的算术强度约 1 FLOP/B；A100 的拐点约 156 FLOP/B。

### 2.6 显存容量（VRAM）

**是什么**：GPU 板载的 HBM 容量，存放权重、KV Cache、激活值和临时缓冲区。

**为什么需要**：容量不够不是变慢，是直接 OOM 跑不起来；它比算力更硬。

**在系统里的位置**：决定单卡能跑多大模型、能开多长上下文、能开多大 batch。

**记住这个数**：RTX 4090 24GB，A100/H100 80GB，8×H100 共 640GB。

### 2.7 Prefill 与 Decode 的两种瓶颈

**是什么**：Prefill 一次性处理全部输入 token，是大矩阵乘法，算力密集；Decode 每步只处理一个新 token，是矩阵乘向量，带宽密集。

**为什么需要**：两者的优化手段完全相反——Prefill 要更多 FLOPS，Decode 要更高带宽和更大 batch。

**在系统里的位置**：第 7 篇推理流程的硬件解释，也是第 13 篇输出定价的根因。

**记住这个数**：7B 模型 Prefill 1000 token 约 50ms，Decode 1000 token 约 5,000–10,000ms（第 13 篇原文口径）。

### 2.8 量化（Quantization）

**是什么**：把 fp16 权重压成 int8/int4，用更少比特表示同一个数。

**为什么需要**：显存直接除以 2 或 4，同时带宽压力同比下降，decode 更快。

**在系统里的位置**：部署侧的第一优化手段，和蒸馏、剪枝并列，但收益最直接。

**记住这个数**：fp16→int4 是 4 倍压缩，7B 从 14GB 降到 3.5GB。

## 3. 手算推演

**第一步：算要读多少字节。** 7B 参数，fp16 每参数 2 字节：7×10⁹ × 2 = 14×10⁹ B = **14 GB**。Decode 每生成一个 token，全部权重都要从显存读进核心一次，一个字节都省不掉（batch=1 时）。

**第二步：除以带宽。**

| 硬件 | 带宽 | 计算式 | 理论耗时 |
|---|---|---|---|
| A100 80GB | 2,000 GB/s | 14 ÷ 2,000 | **7.0 ms** |
| H100 SXM | 3,350 GB/s | 14 ÷ 3,350 | **4.18 ms** |
| CPU DDR5 双通道 | 80 GB/s | 14 ÷ 80 | **175 ms** |

换算成每秒 token 数：A100 约 143 token/s，H100 约 239 token/s，CPU 约 5.7 token/s。

**第三步：和原文实测对照。** 原文给的区间是 CPU 200–500ms、A100 5–10ms。

- CPU 的理论 175ms 是“峰值带宽 + 大块连续读”的理想值。实测 200ms 对应有效带宽 70 GB/s，500ms 对应 28 GB/s。差距来自：DDR5 双通道实际很难跑满峰值、每层的小矩阵读取不连续、KV Cache 和激活值也要占带宽、操作系统调度与页表开销。理论值是下限，不是预期值。
- A100 的 7ms 落在 5–10ms 区间内。值得注意：5ms 一端需要 2.8 TB/s 的有效带宽，超过 A100 的 2.0 TB/s 峰值，只能来自 int8 量化（约 7GB，算得 3.5ms）或原文的量级口径；若按 LLaMA-7B 实际约 6.74B（13.5GB）算，理论值是 6.7ms。10ms 一端对应有效带宽 1.4 TB/s，是正常水平。**原文口径以 5–10ms 区间给出，7ms 的理论值正好居中。**

**第四步：用算术强度校验。** 一步 decode 的计算量约 14 GFLOP（2×参数量），搬运 14 GB，算术强度 = 14÷14 = **1 FLOP/B**。A100 的拐点是 312 TFLOPS ÷ 2 TB/s = **156 FLOP/B**。1 比 156 小两个数量级，所以绝对是带宽瓶颈。纯算力时间只有 14÷312,000 = **0.045ms**，和 7ms 差 156 倍——算力在这里几乎完全闲置。

**第五步：算训练显存。** 7B、混合精度、Adam：

| 项目 | 计算 | 大小 |
|---|---|---|
| 参数 fp16 | 7e9×2 | 14 GB |
| 梯度 fp16 | 7e9×2 | 14 GB |
| Adam m | 7e9×4（fp32） | 28 GB |
| Adam v | 7e9×4（fp32） | 28 GB |
| fp32 主权重 | 7e9×4 | 28 GB |
| 小计（不含激活） | | **112 GB** |
| 激活（32 层×2048 token×4096 维×约 12 个张量×2B） | | 约 6.4 GB（batch=1） |

原文口径把优化器状态记作 56GB（只算 m+v），加上参数 14、梯度 14，再加大几十 GB 激活，结论是“远超 100GB”。补上 fp32 主权重后是 112GB，加激活 118GB，和原文结论一致。一张 80GB A100 装不下；用 ZeRO-3/FSDP 把 112GB 切到 8 张卡，每卡约 14GB 状态加激活才跑得动。

**第六步：核对矩阵乘法的量级。** 4096³ = 68.7×10⁹ 次乘法，乘加算 2 次运算，得 137.4 GFLOP，即原文的“约 1370 亿次”。16,777,216 个输出元素分给 16,384 个核心，每个核心约 1,024 个元素。

## 4. 代码逐行

```python
for step in range(n_out):                 # ① Decode 串行，每步一个 token
    h = embed(last_token)                 # ② 只处理 1 个位置，算力需求极小
    for l in model.layers:                # ③ 32 层，逐层读权重
        h = h + attn(rmsnorm(h), kv[l])   # ④ 读 Wq/Wk/Wv/Wo 四个矩阵
        h = h + ffn(rmsnorm(h))           # ⑤ 读 W1/W2/W3，约占参数 2/3
    logits = h @ W_head                   # ⑥ 读输出投影，词表越大越贵
    last_token = sample(logits)           # ⑦ 采样，几乎不耗算力
# 每步 HBM 流量 ≈ 14 GB，与 batch 大小近似无关
t_step = 14e9 / 2000e9                    # ⑧ A100 上约 7ms
```

① 对应 2.7 的串行性，也是输出单价的根源；② 说明为什么 GPU 利用率只有 10–20%；③④⑤ 是权重读取的主体，FFN 占大头；⑥ 常被忽略，但 128K 词表的输出层本身就有 0.5B 以上参数；⑦ 证明采样不是瓶颈；⑧ 就是本篇的核心公式：**时间 = 字节数 ÷ 带宽**。

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 一个数学教授 vs 一万个小学生 | CPU 少核强单核，GPU 多核弱单核 | 小学生不会自己分工，GPU 需要程序员和编译器显式切 tile、排流水；而且“人多”解释不了带宽和显存这两个独立约束 |
| 数据要快速喂到计算核心 | 内存带宽决定 decode 速度 | 搬运不是“多叫几个人”就行，HBM 焊在芯片旁，带宽是硬件规格；而且 batch 变大能让同一批权重摊薄到多个 token，比喻里没有这层复用 |
| GPU 是大模型时代的“水电煤” | GPU 作为基础设施 | 水电同质、可替换、按用量计费；GPU 有 CUDA 生态锁定、显存上限和型号差异，训练卡和推理卡的需求根本不是同一种商品 |
| CPU 是什么都会的全能选手 | CPU 擅长分支、循环、调度 | 现代 CPU 也有 SIMD 和多核，“全能”不等于适合；矩阵乘法不需要分支预测，CPU 的强项在这里正好用不上 |

## 7. 五个误区

❌ GPU 快是因为主频高 → ✅ 主频甚至比 CPU 低，快在核心数和带宽 → 因为并行度把“串行时间”换成了“吞吐量”，矩阵乘法正好有 1600 万个独立任务。

❌ 看 TFLOPS 就能判断推理速度 → ✅ Decode 看带宽，算术强度只有 1 FLOP/B → 因为每步只算一个 token，算力大量闲置，A100 的 312 TFLOPS 实际只用到零头。

❌ 显存只影响 batch size → ✅ 它首先决定模型能不能装下（权重+KV+激活） → 因为装不下是 OOM，不是变慢；batch 只是装下之后的余量分配。

❌ H100 比 A100 贵只是因为算力强 → ✅ 带宽从 2.0 提到 3.35 TB/s，decode 直接快 1.67 倍 → 因为推理的瓶颈在搬运，带宽提升对 decode 是线性收益，算力提升几乎用不上。

❌ 量化只是为了省显存，精度一定崩 → ✅ 4 倍压缩让 7B 进 24GB，且带宽同比下降、decode 更快 → 因为精度损失取决于量化方法和校准数据，int4 在 7B 以上通常可接受。

## 9. 自测 8 题（含答案要点）

**概念题**

1. 为什么矩阵乘法适合 GPU？
   **答案要点**：输出元素之间完全独立，可同时计算；运算只有乘加，不需要分支预测；GPU 用几千个弱核心换吞吐。

2. 训练和推理的瓶颈为什么不同？
   **答案要点**：训练要反传、要存激活，计算密集且显存巨大；推理 decode 每步只处理一个 token，权重复用率为 1，带宽密集。

3. 什么是算术强度？为什么 7B 的 decode 一定是带宽瓶颈？
   **答案要点**：每字节的浮点运算数；7B decode 约 1 FLOP/B，远低于 A100 拐点 156 FLOP/B。

4. 为什么 H100 对 decode 的提升接近带宽比例？
   **答案要点**：时间 = 字节数÷带宽，权重字节数不变，带宽 2.0→3.35 TB/s，理论提速 1.67 倍。

5. 量化为什么能同时省显存和加速？
   **答案要点**：权重字节数减半或四分之一，容量和每步搬运量同比下降，decode 时间随之下降。

6. 为什么“显存装不下”比“算得慢”更严重？
   **答案要点**：慢还能跑，装不下直接 OOM；权重、KV、激活是硬上限，不能靠时间换。

**计算题**

7. 70B 模型 fp16，在 A100 和 H100 上各生成 100 个 token 的理论时间？
   **答案要点**：140GB 权重；A100 140÷2000 = 70ms/token，100 个 7.0s；H100 140÷3350 = 41.8ms，100 个 4.18s。

8. 24GB 的 4090 跑 7B int4，权重占多少、还剩多少给 KV、按 512KB/token 能开多长上下文？
   **答案要点**：7e9×0.5 = 3.5GB；剩 20.5GB；20.5e9÷524,288 ≈ 39,100 token；带宽 1,008 GB/s 时单步约 3.5ms。

## 10. 一页速记

- 矩阵乘法 = 大量独立乘加，是 GPU 的完美负载。
- CPU 少核强单核，GPU 多核弱单核，吞吐靠数量。
- 训练看算力，推理 decode 看带宽。
- 7B fp16 权重 14GB，decode 每步必须完整读一遍。
- 时间 = 字节数 ÷ 带宽，这是本篇唯一的核心公式。
- A100 7ms、H100 4.18ms、DDR5 175ms，差距全在带宽。
- 算术强度 1 FLOP/B，远低于拐点，算力在 decode 时几乎闲置。
- 训练 7B 需 112GB 状态加激活，单卡 80GB 装不下。
- 量化把权重压 4 倍，先解决装得下，再解决跑得快。
- 显存是硬约束，OOM 不会因为等待而变好。

三个关键数字：**14 GB**（7B 的 fp16 权重）、**2,000 GB/s**（A100 带宽）、**7 ms**（一步 decode 的理论下限）。
