# 第 14 篇精读｜思考模式：模型只是先给自己打了份草稿

> 原文：llm-14-thinking-mode.md ｜ 前置：第 13 篇 ｜ 核心一句话：思考模式没有新架构，只是让模型在回答前多生成一串普通 token 当草稿纸，用多次前向的串行算力换准确率。

## 0. 三句话抓住它

- 思考 token 就是普通输出 token，一样按最贵的输出价计费。
- 每多一个 token 就多跑一次 32 层前向，用步数换深度。
- 开不开只看：多付的钱能否被"少错几次"赚回来。

## 1. 这一篇在补哪个洞

这是番外篇四，位置上挂在正篇第七篇（推理与 Decode）之后，同时回接第四篇 Attention、第五篇 Transformer 全景和第九篇 Scaling Law。正篇把"生成"讲透了，却留下一个产品级的问题没有回答：同一个模型，权重没变、架构没变、参数量没变，为什么点一下"深度思考"按钮就明显变强？多出来的能力不可能凭空产生，它必须有一个物理来源。

它补的第一个洞是"算力从哪来"。第五篇说一层 Transformer 的深度是固定的，第七篇说每个 token 需要一次完整前向。两句话拼在一起是个坏消息：再难的问题也只给 32 层，和"1 + 1"拿到的算力一模一样。思考模式是对这个硬约束的工程绕行——不加深网络，而是增加串行步数，让同一组权重被反复调用。

它补的第二个洞是"钱花在哪"。番外篇三讲过输出 token 是最贵的一档，而思考 token 恰好 100% 是输出 token。所以这篇实际上是"能力来源"和"账单来源"的合订本，也是全书唯一系统讲 Test-time Compute（推理时 Scaling）的地方。

## 2. 概念逐层拆

### 2.1 思考 token

**是什么**：模型在给出最终答案之前，自己生成的一段普通 token 序列，通常包在 `<think>...</think>` 标记里。

**为什么需要**：Transformer 单次前向的深度固定，难题需要更多串行计算步骤，而"串行"在自回归模型里只能靠"再喂给自己一个 token"来实现。

**在系统里的位置**：和答案 token 走同一条 Decode 循环、同一个 LM Head、同一张计费表；区别只在前端是否折叠展示。

**记住这个数**：思考 token 按输出价计费，原文口径 DeepSeek V4 Pro 输出 24 元/百万 token。

### 2.2 草稿纸效应

**是什么**：中间结果一旦被采样成 token，就进入上下文窗口，后续每个 token 的 Attention 都能直接读到它。

**为什么需要**：心算把中间量放在隐状态里，会被后续层不断覆盖；写下来则变成可反复寻址的外部存储。

**在系统里的位置**：作用在 Attention 的可见范围上——它把"一次前向的内部状态"转成了"跨前向的持久状态"。

**记住这个数**：上下文里多 800 个 token，等于给最后一步预测多 800 条可查记录。

### 2.3 单步算力上限

**是什么**：一次前向固定走 N 层（本例 32 层），与题目难度完全无关。

**为什么需要**：这是理解思考模式的支点——不是模型不想多算，是深度被架构锁死了，只能从"次数"上找补。

**在系统里的位置**：属于训练时定死、推理时不可调的超参；推理时唯一能调的是步数。

**记住这个数**：32 层，难题和口算题分到的算力完全相同。

### 2.4 Test-time Compute

**是什么**：在推理阶段增加计算量来换质量，与训练阶段堆参数、堆数据并列的第二个 Scaling 维度。

**为什么需要**：训练 Scaling 的边际成本越来越高，而推理算力可以按请求粒度购买——简单问题不付，难题才付。

**在系统里的位置**：夹在"模型能力"和"产品定价"之间，是两者之间唯一可实时调节的旋钮。

**记住这个数**：同一个模型可以给出 60% 和 85% 两档准确率，差的只是推理预算。

### 2.5 两阶段训练

**是什么**：SFT 教格式（学会输出 think 段），RL 教质量（哪种推理路径更容易导向正确答案）。

**为什么需要**：预训练语料里没有稳定的"先想再答"格式，必须显式示范；而"想得好"无法靠模仿学习得到，只能靠结果奖励。

**在系统里的位置**：接在正篇第六篇的三阶段之后，SFT 改行为，RL 改策略。

**记住这个数**：SFT 学"有没有 think 段"，RL 学"think 段里写什么"。

### 2.6 思考预算

**是什么**：对思考 token 数量的上限约束，例如 1K / 8K / 32K 档位。

**为什么需要**：思考 token 线性加钱、线性加延迟，必须有刹车；它也让"想多久"变成一个可定价的商品档位。

**在系统里的位置**：在 Decode 循环里做截断，超预算就强制切换到答案阶段。

**记住这个数**：预算翻倍成本就翻倍，但准确率不会翻倍。

## 3. 手算推演

题设：同一道难题，输入 100 token，答案 200 token，思考 800 token；输出单价 24 元/百万 token（原文口径），思考 token 按输出计费。

**Step 1：前向次数**

- 非思考：100 + 200 = 300 token → 300 次前向（原文口径：token 数即前向次数）。
- 思考：100 + 800 + 200 = 1100 token → 1100 次前向。
- 倍数：1100 / 300 = **3.67×**。

**Step 2：输出侧费用**

- 非思考：输出 200 token → 200 / 1e6 × 24 = **0.0048 元**。
- 思考：输出 800 + 200 = 1000 token → 1000 / 1e6 × 24 = **0.024 元**。
- 差额 0.0192 元，倍数 1000 / 200 = **5×**。

注：输入 100 token 按输入价另计，原文未给输入单价，故此处只算输出侧。5× 是上限口径；若把输入也计入总 token，总倍数回落到 3.67×。

**Step 3：每次正确回答的期望成本**

设非思考准确率 60%，思考 85%。

- 非思考：0.0048 / 0.60 = **0.0080 元/次正确**。
- 思考：0.024 / 0.85 = **0.02824 元/次正确**。
- 比值：0.02824 / 0.0080 = **3.53×**。

注意这个 3.53× 小于 5×——准确率提升消化掉了一部分涨价。

**Step 4：边际成本（决策线）**

取 100 道题：

- 非思考：花 0.48 元，答对 60 题。
- 思考：花 2.40 元，答对 85 题。
- 多花 1.92 元，多对 25 题 → **每多对一题 0.0768 元 = 7.68 分**。

这个 7.68 分就是盈亏平衡点：一次答错的代价（人工复核、返工、用户流失）高于 7.68 分，开思考才划算。

**Step 5：什么时候不值得**

换成简单问答：准确率 95% → 98%，只多对 3 题，仍多花 1.92 元 → 每多对一题 **0.64 元**，是难题场景的 8.3 倍。准确率越高，思考的边际收益越差。

所以判据不是"这题难不难"，而是"**这题错了贵不贵** × **思考还能救回多少**"。

**Step 6：一句话结论**

5× 成本换 1.42× 正确率，期望成本 3.53×；只有当"错一次"值 7.68 分以上时，这笔交易才成立。

## 4. 代码逐行

原文无脚本，以下为机制的 15 行伪代码复现。

```python
def generate(prompt, thinking_budget=0, max_new=200):
    ctx = tokenize(prompt)                     # 输入 100 token，只做一次 Prefill
    think = []                                 # 草稿纸：本质就是一个 token 列表
    while len(think) < thinking_budget:        # 预算刹车，对应 2.6
        logits = forward(ctx + think)          # 一次完整 32 层前向
        think.append(sample(logits[-1]))       # 落笔：采样即写入上下文
    answer = []
    while len(answer) < max_new:
        logits = forward(ctx + think + answer) # 答案能看到全部草稿
        answer.append(sample(logits[-1]))
        if answer[-1] == EOS: break
    return detokenize(answer)

# 成本 = (len(think) + len(answer)) * 输出单价   ← 5× 的全部来源
```

逐行对应：

- `tokenize`：对应第 2 篇分词，属于预处理，不是算子。
- `ctx` 只算一次：对应第 7 篇，输入部分可并行 Prefill。
- `think = []`：对应 2.1，思考没有任何特殊数据结构，就是普通 token。
- `while len(think) < budget`：对应 2.6，预算是唯一刹车。
- `forward(ctx + think)`：对应 2.2，草稿拼进上下文，Attention 才看得见。
- `logits[-1]`：只取最后一个位置，因果掩码保证不看未来。
- 第二个 `while`：和第一个是同一套代码，只是不再受预算限制。
- 最后一行注释：一行算出思考模式贵在哪。

## 5. 数字与公式速查

| 量 | 值 | 含义/出处 |
|---|---|---|
| 非思考总 token | 300 | 100 输入 + 200 输出，原文第五节 |
| 思考总 token | 1100 | 100 + 800 + 200，原文第五节 |
| 思考阶段输出 token | 800 | 全部按输出价计费 |
| 输出单价 | 24 元/百万 token | 原文口径（DeepSeek V4 Pro） |
| 单题输出成本比 | 5× | 1000 / 200，仅输出侧 |
| 总 token 比 | 3.67× | 1100 / 300 |
| 期望成本比 | 3.53× | (0.024/0.85) ÷ (0.0048/0.60) |
| 边际成本 | 0.0768 元 | 1.92 元 ÷ 25 道多对的题 |
| 前向深度 | 32 层 | 一次前向的固定层数 |
| 准确率档位 | 60% → 85% | 题设 |

核心公式：

- 期望成本 = 单次成本 ÷ 准确率
- 边际成本 = Δ总成本 ÷ Δ答对题数
- 前向次数 ≈ 总 token 数（原文口径，忽略 Prefill 的并行性）

## 6. 类比拆解

| 原文类比 | 它映射到哪一步 | 这个比喻在哪儿会失效 |
|---|---|---|
| 草稿纸 | 思考 token 进入上下文，供后续 Attention 引用 | 人写草稿会回头验算；模型不会，错误的中间步骤会被当作事实一路推到底，越写越自信 |
| 考试只给 10 秒 | 一次前向固定 32 层，难题也算力不足 | 考试到点必须交卷；模型可以一直拖，约束它的不是时间而是 token 预算和钱包 |
| 32 × 101 层的推理链 | 多步前向串行叠加 | 真正的 3232 层网络每层有独立权重、能学新特征；这里只是同一组 32 层权重被反复调用 |
| 心算 vs 笔算 | 隐状态推理 vs 上下文推理 | 人笔算有校验环节，模型没有"回头检查"的机制，写完即定稿 |

## 7. 五个误区

❌ 思考模式是一种新架构 → ✅ 架构一字未改，还是同一套 Transformer 预测下一个 token → 因为所有"思考"都发生在 token 空间，不在网络结构里。

❌ 思考 token 是内部计算，不该收费 → ✅ 它就是输出 token，按最贵档位计费 → 因为计费只看"生成了多少 token"，不看这 token 给谁看。

❌ 想得越久一定越准 → ✅ 超过某个长度后准确率会持平甚至下降 → 因为错误的中间步骤会污染上下文，模型倾向于自洽而不是自纠。

❌ 思考模式适合所有任务 → ✅ 简单问答、翻译、摘要上收益接近零，成本却是 5× → 因为这类任务没有多步可拆，深度根本不是瓶颈。

❌ 思考模式就是 Agent → ✅ 思考在模型内部跑，Agent 在外部调工具 → 因为前者改变上下文长度，后者改变信息入口。

## 9. 自测 8 题（含答案要点）

**1. 概念：思考模式和普通模式在架构上有什么不同？**
答：没有不同。同一套权重、同一套 32 层、同一个 LM Head，区别只在生成序列里多了一段被标记为 think 的 token。

**2. 概念：为什么"多生成 token"等价于"多给算力"？**
答：自回归生成每出一个 token 就要跑一次完整前向；N 个 token 就是 N 次 32 层计算，且后一次能看见前一次的结果，形成串行推理链。

**3. 概念：草稿纸效应具体作用在哪个机制上？**
答：作用在 Attention 的可见范围上。中间结果变成 token 后进入上下文，后续预测可以对它做注意力加权，相当于把内部隐状态外化成可寻址存储。

**4. 概念：SFT 和 RL 在思考模式训练里各负责什么？**
答：SFT 用带推理过程的问答对教"格式与套路"，让模型学会先输出 think 段；RL 用结果奖励优化"哪条推理路径更容易对"，教内容质量。

**5. 概念：为什么思考模式的成本涨幅（5×）比总 token 涨幅（3.67×）更大？**
答：因为新增的 800 个 token 全部落在输出侧，而输出单价远高于输入单价；分母里那 100 个便宜 token 被稀释掉了。

**6. 概念：什么任务不该开思考模式？判据是什么？**
答：没有多步可拆、且错误代价低的任务，如闲聊、翻译、摘要、简单事实问答。判据是"错误成本 vs 每多对一题的边际成本"。

**7. 计算：输入 100、思考 800、输出 200，输出价 24 元/百万，求两种模式输出侧费用与倍数。**
答：非思考 200 × 24 / 1e6 = 0.0048 元；思考 1000 × 24 / 1e6 = 0.024 元；倍数 5×，差额 0.0192 元。

**8. 计算：准确率 60% → 85%，求每多答对一题的边际成本；若"错一次"的成本是 0.05 元，是否值得开？**
答：100 题多花 1.92 元、多对 25 题，边际成本 0.0768 元。0.0768 > 0.05，不值得开。

## 10. 一页速记

- 思考 = 回答前先生成一段普通 token，没有新架构。
- 每 token 一次完整前向，32 层不变，变的是步数。
- 草稿写进上下文，后续 Attention 直接引用。
- 思考 token 按输出价计费，是最贵的那一类。
- 本例 5× 输出成本，换 60% → 85% 准确率。
- 期望成本 0.0080 → 0.0282 元，3.53×。
- 边际成本 7.68 分/多对一题，这才是决策线。
- 训练靠 SFT 学格式、RL 学质量。
- 预算才是刹车，长度不是越长越好。
- Test-time Compute 是第二个 Scaling 维度。
- 思考是内部多步，Agent 是外部多步。

关键数字：**32 层**、**5×**、**0.0768 元**。
